# SKILL: 变异测试 —— 给你的判据打分

**一句话**：「测试全绿」只说“我测过的都对”；**变异得分说“我没测到的有多少”。**

---

## 一、它是什么

主动**制造错误**，看你的判据抓不抓得住：

```
对一个能跑的实现做单点变异（翻转比较符 / 改一个常量 / 删一行）
逐个喂给你的判据
  判据变红 = 杀死（判据看见了）
  判据仍绿 = 存活（← 这是判据的真实盲区，可以逐行看出来）
变异得分 = 杀死 / 可用变异
```

**它测的不是代码，是你的判据。**

---

## 二、跑法

```bash
# 单臂
node tools/mutate.cjs --impl impl.js --checker check.cjs --max 30

# 门禁（读 floors 文件，低于地板就 exit 1）
node tools/gate.cjs
```

`--max` 是抽样数。**抽样数不同，得分不可比**（见第四节）。

## 三、实测：它抓到了判据抓不到的 bug

在一个 15 个 op 的项目里，用 20 条判据量两份实现：

| 实现 | 变异得分 | 存活 |
|---|---|---|
| 宏实现 | 82.0% | 9 |
| 表实现 | 54.3% | 16 |

**存活变异全部集中在判据没喂过的输入类型上**：

```
宏实现：6/9 在 JSON 读写层
  · 转义 \ 的分支      · 布尔字面量 false
  · 小数点判断          · 指针前进 4
  · 字符串直通          · 跳过空白

表实现：集中在字段语义
  · normalizePatch 里 name/teacher/location 被删（整类字段静默丢弃）
  · swap 不交换 periodFrom
```

依此补了 6 条判据后，**当场抓到两个真 bug**：

```
① emoji 被写成 \u1F40B —— \u 只有 4 位，增补平面必须拆成代理对 \uD83D\uDC0B
② weeks:{} 被写成 null —— 空对象与"缺失"在解析后不可区分
```

**这两个 bug 在 20 条全绿的判据下面藏了整晚。** 而变异测试**提前指出了位置**。

## 四、四条必须知道的口径（不知道就会误读）

### 1. 得分依赖抽样数

同一份代码、同一批判据：

| 抽样 | 宏实现 | 表实现 |
|---|---|---|
| 50 / 60 | 84.0% | 74.3% |
| 30 | 83.3% | 64.7% |

**地板分必须绑定抽样数。** 改抽样 = 改地板 = 重测。

### 2. 语法无效的变异要排除

JS 上 30 个抽样里有 13 个语法就坏了（`===`→`!==` 撞进表达式、删行删在语句中间）。
它们不能算"存活"。**这是变异器的粗糙，不是"这门语言更抗改"。**

要让变异更有效，得让规则懂语法边界（用 AST 而不是正则）。

### 3. 基线必须全绿才能计分

基线本来就有红的判据时，**任何变异都"有失败"**，于是全被记成"杀死" —— 会跑出 100% 的假象。

正确做法：**按"变异引入了基线没有的新失败"判定**（本工具的 `gate.cjs` 已内置）。

### 4. 两个得分不能比"代码质量"

它比的是「**同一批判据对两份实现的有效性**」。
得分低只说明"这份实现的某些行为，你的判据看不见"。

## 五、断言别锁定实现偏好

补判据时最容易犯的错：**把某一种实现的措辞当成契约**。

实测踩过三次：

```
✗ 断言「periodTo 必须等于 2」
   规格只说"不得倒挂"，两臂都选择把 periodTo 抬上去 —— 合规，不是错

✗ 断言「清空空周的日志要有『没有课』」
   那是某一份实现的文案，不是规格

✗ 用 match:"" 空串（语义未定义）来测"匹配全部"
   两臂行为本就不同，无从判对错
```

**规则**：只断言语义要点（“提到操作 + 数量”“不得倒挂”），
要把措辞或未定义行为钉死，**先由规格拍板**，再写判据。

## 六、门禁怎么写

```json
{
  "sample": 30,                 // 地板与抽样数绑定
  "floors": {
    "arm-a/impl.lisp": 83.3,    // 只能上调，不许下调
    "arm-b/impl.js":   64.7
  }
}
```

```
① 地板只能手动上调；下调必须在提交信息里写清理由
② 改抽样数 = 改地板，必须重测
③ 基线不全绿 → 拒绝计分（按"新增失败"判定）
④ 门禁本身要先证明能红：调高地板 → 必须 FAIL
```

---

## 七、它和普通测试的分工

| | 测试全绿 | 变异得分 |
|---|---|---|
| 回答的问题 | “我测过的都对吗” | “我没测到的有多少” |
| 会随时间变差吗 | 不会（加了代码还是绿） | **会**（实现变复杂、判据没跟上） |
| 能指出下一步写什么判据吗 | 不能 | **能**（存活变异逐行列出） |

> **一次性的测试覆盖率是幻觉，变异得分是体温计。**
> 每次改判据或改实现，都该量一次。
