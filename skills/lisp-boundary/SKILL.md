# SKILL: 边界 —— 内部表示与外部世界之间那两层

**一句话**：一个程序只有两个地方该知道"数据的内部形状"——**读进来的地方**，和**写出去的地方**。
这两层之间的所有代码，都该看到裸值。

---

## 一、这个坑有多贵

实测（2026-10-24，一个 5 op 的课表程序）：

```
Unhandled TYPE-ERROR: The value :OBJ is not of type LIST
0: (SB-KERNEL:%ASSOC-TEST "name" (:OBJ ("name" "高数") …) #<TWO-ARG-STRING=>)
1: (CGET (:OBJ …) "name")  2: (NAME-OF …)  3: (MATCH-COURSES "高数")  6: (OP-DEL …)
```

**症状**：9 条判据里 7 条一次全红，报错一律 `stdout 非 JSON`（因为整个程序在第一个 op 上就崩了）。
**根因**：解析器给对象打了 `:obj` 标签（为了区分"对象"和"数组"），而业务函数 `cget` 只认裸 alist。
**修法**：2 行，**只在边界做转换**——进门 `(copy-tree (cdr c))` 摘标签，出门 `(cons :obj c)` 戴回。

灾难不在于难修，而在于：**修完之后 14 条判据一次全过**，你会以为前面那 7 个红是七种不同的错。

### 一条通用诊断规则（第二次实测验证）

**看到"全部判据同时报 `stdout 非 JSON`"，先看 stderr，别当成多种错。**

这类全红几乎总是**一个**根因，而且通常是下面三种之一：

```
① 边界标签泄漏进业务层（本篇主角）
② 写出层的某个细节错（例：loop 用 on 而不是 in，见 lisp-json 第四个坑）
③ 输出编码/编码残留（BOM、CRLF、代理对）
```

判据只会说"你的 stdout 不是 JSON"，因为程序在**第一个 op** 就崩了。
所以排查顺序永远是：`直跑 → 看 stderr 第一行 → 定位是①②③哪一种 → 再改`。

## 二、为什么 Lisp 必须打标签

在 JS / Python / JSON 里，这五个值天然不同：

```
null ≠ {} ≠ [] ≠ false ≠ 0
```

在 Common Lisp 里，`nil` **一个人演四个角色**：

```
nil = 空列表 = 假 = 空数组 = 缺失
```

所以你要如实表达 JSON，就必须自己造标签，例如：

```lisp
:null        ; JSON null
(:obj)       ; 空对象 {}
'()          ; 空数组 []        ← 用 nil 本身
:true :false ; 布尔
```

**不打标签的后果**（实测过的）：`{"weeks":{}}` 被写成 `"weeks":null`——
因为 `{}` 解析成 `nil`，而写出处 `(or (course-weeks c) :null)` 把 `nil` 当成了"缺失"。

## 三、三条契约（照抄）

### 契约 1：标签只活在两个函数里

```
parse-json      → 返回带标签的内部值
unwrap / wrap   → 边界转换（各一处）
```

**业务层（`cget` / `set-fld` / 每个 op 的 body）只接受裸 alist 与标量。**

### 契约 2：进出各转换一次，不许"顺手"转

```lisp
;; 进门：列表里每个元素摘掉 :obj
(mapcar (lambda (c) (copy-tree (cdr c))) (cdr (cget al "courses")))

;; 出门：写回时戴回
(cons :obj c)
```

**只在这两处出现 `:obj`。** 如果 `grep -c ':obj'` 的结果大于 4（标签定义 + 两处转换 + 常量表），
说明你把它漏进业务层了。

### 契约 3：三个"空"必须输出不同

```lisp
:null  →  "null"
(:obj) →  "{}"
'()    →  "[]"
```

写完先跑这三条，再看别的。**它们是这条边界最容易被压扁的地方。**

## 四、边界还有哪些项（同一类，一起处理）

| 边界项 | 症状 | 做法 |
|---|---|---|
| **BOM** | SBCL 报 `The variable ﻿ is unbound` | 写文件用 `[IO.File]::WriteAllText` + `UTF8Encoding($false)`，别用 `Set-Content -Encoding utf8` |
| **stdout 编码** | 中文/emoji 变成 `?` 或 `\u1F40B` | 先探：`(stream-external-format *standard-output*)`；SBCL 平时就是 `:UTF-8`，**直接输出原文，不要写转义兜底** |
| **增补平面字符** | emoji 写成 `\u1F40B`（非法 JSON，`\u` 只能到 FFFF） | 真要转义就拆代理对：`\uD83D\uDC0B` |
| **数字类型** | 整数被写成 `2.0`，浮点被写成 `2.5d0` | 写整数走 `~d`，写浮点走 `~f`，不要一个 `~a` 打通 |

## 五、写完之后的三问

```
1. grep ':obj' 出现在哪几个函数里？（应当是 2–4 处，且都在边界）
2. 输入 {"weeks":{}} 和 {"weeks":null} 和 {"weeks":[]}，输出分别是 {} / null / [] 吗？
3. 打印一个中文 + 一个 emoji，stdout 是原文还是转义？
```

三问任一不过，就先修边界，**别去动业务逻辑**——边界错了，业务层的红全是假信号。
