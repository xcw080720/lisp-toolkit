# SKILL: defop —— 把「一个 op 的知识」压成一处

## 何时用

- 你已经在同一份代码里写过 2 个以上的同类 op（增/删/改/移这类），并且**每加一个都要改 3 处以上**；
- 或者你已经知道将来会有 ≥10 个同类 op。

**不要**在只有 1–2 个 op 时套它。实测交叉点在 19–34 个 op（熟练度低时），熟练后可能降到 10–18。

## 形态

```lisp
(defop "add"
  (:need ("course" ("course" "name")))
  :text ("加「~a」" ("course" "name"))
  (lambda (s op) ...))          ; 执行体
```

一条声明同时长出：**参数校验、确认文案、执行逻辑、日志、名册登记、分发**。

## 它到底省什么（实测，别听传说）

| 项 | 有无宏 |
|---|---|
| 每 op 新增行（纯横切） | 有宏 2–3 行；手写 20–30 行 |
| 加 op 的触点 | 有宏 1 处；手写 3–4 处 |
| 加"审计"这种横切能力 | **与宏无关**，见下 |

## 三条边界（今晚验证过的，别指望宏做更多）

1. **覆盖「按 op 的横切」**——校验/文案/日志/分发/名册，一次声明长出。
2. **不覆盖「字段纵切」**——新增一个字段仍要动模型、拷贝、序列化等 4 处。宏吸收不了。
3. **不覆盖「跨 op 的框架层」**——日志聚合、整批拒绝这类，要单独写。

## 横切关注点（审计/权限/重试）：真正的分界线不是宏

实测三臂加"审计"：

| 写法 | 改动处数 |
|---|---|
| 宏（`run-all`/`emit`/`main` 三处签名链） | 3 |
| 表驱动（循环 + 出参） | **1** |
| 手写 `cond`，但分发器已返回 per-op 计数 | 4（且 0 处 per-op） |

> **O(1) 的前提是"分发器有一个统一漏斗，且它携带 per-op 元数据"。**
> 有漏斗就 O(1)，跟有没有宏无关。宏只是让漏斗写起来短。

## 组合深度是免费的（唯一像复利的地方）

```lisp
(defop-chain "triple1" ("match") ("pair1") ("mark1"))
```

已注册的 op 可以当零件喂回去，**每加一层不新增基建**。
实测：层内每 op 恒定 2 行；层间一次性台阶 4–19 行。

## 反模式

- 手写 `known-op-p` 名单 → 必漏。让宏登记。
- 手写 `one-op-text` 的每 op 分支 → 必漏。让宏长出。
- retrofit：把已有手写实现改成 defop，实测 **+142 行**，需要 N > 71 才回本。别在大项目后期干这个。
