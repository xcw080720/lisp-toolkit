# SKILL: v3 时代的技能包 —— 只给 v3 实验用

> 从 2026-10-31 起，实验换到 `experiments/PROTOCOL-v3.md`。
> 技能包不是"越多越好"：**v3 里只给这一篇 + `lisp-defop` + `lisp-macro-value` 三篇**。

---

## 一、v3 的任务长什么样（先记死，别改）

| 项 | 值 |
|---|---|
| op 数 | **15** |
| 输入 | 命令行参数（argv） |
| 输出 | stdout 纯文本，每行一条结果 |
| 禁止 | **JSON、序列化、文件读写、第三方库** |
| 单文件 | 是 |

**为什么禁 JSON**：它已经量化过了——CL 手写 2547 字符、JS 内置 233，占掉全部差异的 40%。
v3 要测的是"语言 + 方案"，不是"谁自带库"。

## 二、三种实现风格（要说清，不许暧昧）

| 风格 | 一句话定义 | 判定标准 |
|---|---|---|
| `macro` | 每个 op 只有一条表单；校验、文案、日志、分发、名册由宏生成 | 15 个 op 对应 15 条表单 |
| `table` | 一张注册表描述所有 op，执行器读表分发 | 15 条表项 + 1 个执行器 |
| `inline` | 每个 op 独立手写分支，**不共用任何生成机制** | 15 个互不引用的分支 |

**`inline` 是基准臂**：它代表"不用任何语言技巧"的写法。任何声称"Lisp 更省"的说法，都必须在 `inline` 对上仍成立才作数。

## 三、写代码时唯一要遵守的两条

1. **单一知识源**：每个 op 的字段、校验、输出模板只写一次。
2. **错误要落在地上**：非法输入必须产生一条明确的输出行，不许静默跳过（静默失败是这个实验里最贵的错）。

## 四、别做的事（踩过的坑）

| 坑 | 后果 |
|---|---|
| 用行数衡量自己 | 行数测的是排版。用 `metric.cjs` |
| 把 JSON 手写塞进"语言成本" | 那是库的缺口，不是语言 |
| 只交一份实现 | n=1 没有方差，等于没测 |
| 自测完就删日志 | 返工轮数只能从日志里读 |

## 五、数字（截至 v1.1.2，写进技能包是为了不再说错）

| 说法 | 状态 |
|---|---|
| ~~CL 比 JS 长 1.93 倍~~ | **降级**：只在一种方案下成立 |
| 同规模、三种方案（宏/表、内联、迭代）下 CL/JS = **1.89–2.16** | 成立，但 n=1 |
| 差异的 **~40%** 来自 I/O 生态（CL 手写 2547 / JS 内置 233） | 成立 |
| "Lisp 家族天然冗长" | **不成立**：Julia（Lisp 系宏语言）core 3225，比 JS 的 5718 短四成 |

## 六、v3 里怎么用这些数字

- 不要用它们当结论，用它们当**先验**：v3 的 H1 预测 CL 在 core 上仍高于 JS，但差距应小于 1.9×（因为 I/O 被拿掉了）。
- 如果 v3 测出 CL ≈ JS，说明**剩下的差异本来就是库**，那 H1 被反驳，记进 CLAIMS，不解释。
