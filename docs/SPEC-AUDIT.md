# 题面检查清单（SPEC-AUDIT）

> 起因：2026-10-31 第 6 次判据错误（verb 大小写），它是**唯一一次跑多少遍都不会暴露**的错。
> 用法：每次冻结 spec 之前，逐条走这张表；每条都要回答「哪条判据覆盖它」。

---

## 一、为什么需要这张表

六次判据错误分两类：

| 类 | 错误 | 谁抓到 |
|---|---|---|
| **A 类**：期望值算错 | shift 参数个数、move 参数个数、trim 的 n、add 冲突、判据超范围 | **跑一遍现有实现就暴露** |
| **B 类**：读漏规格 | verb 大小写（规格 L39 明写小写，判据写成驼峰） | **只能靠逐条读规格** |

B 类最危险：**当判据与实现在同一处读漏，判据永远不会失败。**

### 已补上的缺口（2026-10-31，判据 77–80）

`teacher`/`loc` 可为 `-`、12 字符边界、`-` 可被 edit 覆盖——三条规格明文原本无判据，现已补成 #77–#80。13 格中无一格在这四条上失败，说明实现本身正确，但此前**完全不受约束**。

### 仍然存在的两个缺口

**缺口 1：行尾空格 / `\n` 结尾（L61）**
现有 checker 按行比对，天然会抹掉行尾差异。要测它得改成逐字节比对末尾。
**影响**：低（不影响语义），但它是明文要求，按纪律必须记。

**缺口 2：不得依赖当前工作目录（L124）**
现有 checker 总是从同一个工作目录调用。要测它得加一个「换 cwd 再跑一次」的模式。
**影响**：中（子代理报告里提到过有人踩坑：argv 定位依赖 cwd）。

## 三、每次冻结前的操作步骤

1. **把 spec 通读一遍**，把每条"逐字/必须/不得"抄进上面的表
2. 对每一条，写出**覆盖它的判据编号**
3. 任何一行写不出编号 → 要么补判据，要么在"已知缺口"里登记
4. **不要**用"跑一遍看看"代替这一步——B 类错误跑不出来

## 五、一句话

> **A 类错误靠执行暴露，B 类错误只能靠读。**
> 所以每次冻结前，必须有人在**不运行任何代码**的情况下，把规格与判据对读一遍。
