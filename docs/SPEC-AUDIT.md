### 两个已补的缺口（2026-11-01）——以及补的时候踩到的坑

**缺口 1（已补，2026-11-01 改为 #81）：行尾卫生（L61）**

补的时候踩到一个坑，必须记下来，因为它比缺口本身重要：

| 判法 | 普通行尾空格 | **NBSP（U+00A0，字节 `C2 A0`）** |
|---|---|---|
| `/[ \t]$/` | 抓到 | **漏检** |
| `/\s$/` | 抓到 | 抓到 |

**如果按 `[ \t]` 写，#81 对 NBSP 形态的尾空会永远通过。** 而 NBSP 恰恰是最容易从复制粘贴里混进来的字符。

所以 #81 的判定必须是：**行尾不得有任何空白字符**，检查用 `\s`，或按字节显式检查 `0x20 / 0x09 / C2A0 / E38080`（全角空格）。

反例验证（`tmp/probe-81-82.cjs`，两个 JS 变体）：普通尾空格、缺末尾 LF、NBSP 尾空格——三种都能被抓，且原版零误报。

**缺口 2（已补，2026-11-01 改为 #82）：不依赖 cwd（L124）**

反例：把 `process.stdout.write(text)` 改成拼上 `process.cwd()`，两个不同工作目录下输出不同 → 判据必须能抓。

### 补判据这件事本身需要被审查（第二次）

- **第一次**：E-04（2026-10-31）——判据的期望值和实现读漏同一行规格，于是判据永远绿。
- **第二次**：#81 的检查方法比规格窄——规格说"不得有空白"，写成 `[ \t]` 就漏掉 NBSP。

## 三、每次冻结前的操作步骤

1. **把 spec 通读一遍**，把每条"逐字/必须/不得"抄进上面的表
2. 对每一条，写出**覆盖它的判据编号**
3. 任何一行写不出编号 → 要么补判据，要么在"已知缺口"里登记
4. **不要**用"跑一遍看看"代替这一步——B 类错误跑不出来

## 六、不可达分支登记（不补判据）

### `swapDays` 的 CONFLICT

规格 L162 写着「需要查冲突的（`copyTo` / `swapDays`）→ `err CONFLICT`」。

但实测：7 组对抗输入下，**删掉整段冲突检查与基线逐字节相同**。原因是换日标签保持「天内无重叠」这个不变量，所以互换后产生冲突的情况**不可达**。

**给它补判据等于造一个假的绿**——判据会通过，但通过的路径根本不存在。所以只登记，不补。

### 与之对照：`copyTo` 的 CONFLICT 是可达的

`copyTo` 把课复制到同一 cell 的任意时段，目标时段完全可以已被占 → 可达。已补 #83、#84。

**这两者的区别是判断依据，不是猜测：一个在对抗输入下行为不变，一个会变。**

## 八、对外文字纪律（2026-11-01 追加）

这一条不属于判据，但和前七条同一个病根：**把自己做了什么写进了公开记录。**

### 规则

> **能写事实，就别写动作。**
> 「record id 单调递增」是事实；「我试过删除但被拒」是动作，而动作会让人推断动机。

### 两个实例

| 位置 | 写了什么 | 为什么删 |
|---|---|---|
| 未发布的 VERSION-MAP | 「不能删除已发布 record（API 返回 403）」「PUT 直接 500」 | 读者会推：他先想删、删不掉 |
| 已发布的 v1.6.4 notes | 「a reader… would otherwise be right to suspect **concealment**」 | 「隐瞒」这个词是我自己提出来的，没人会往那想 |

**v1.6.4 已发布，改不了。这条记录留作以后的规矩。**

### 判断方法

写完一段对外说明，问一句：**这句话是在陈述可观测的事实，还是在陈述我的尝试？**
后者一律删掉，只留前者。
