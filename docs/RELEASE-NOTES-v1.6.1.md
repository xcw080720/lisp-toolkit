## 一、#31/#32 转正（规格补充 §4.1）

**问题**：判据 `#31`（未知命令 → `BADARG`）、`#32`（空命令串 → `BADARG`）一直要求某种行为，但 `tasks/v3.spec.md`
从未写过这两种输入。于是同批产物能算出两个通过率：全 36 条 **2/12**，剔除这两条 **5/12**。

**处置**：把要求写进规格，而不是把判据剔掉。

- `tasks/v3.spec.md` 新增 **§4.1**，把两条写成明文（并列进 §3 的 `BADARG` 一行）；
- `check-v3.cjs` **删除** `--exclude-out-of-spec` 开关——转正后再留着它，等于允许重新剔掉合规判据；
- 新增 `FREEZE-v1.6.1-amendment.txt`，记录修订后的 spec 与判据哈希；四份历史 FREEZE 各加一行指针，**原有哈希不动**（那是历史事实）。

**后果（必须记账）**：

| | 转正前（剔除口径，已废） | **转正后（唯一口径）** |

| CL first_pass | 5/12 | **2/12** |
| 受影响格 | macro r3、inline r1、inline r3 由"通过"变"失败" | 它们确实没处理未知命令与空串 |
