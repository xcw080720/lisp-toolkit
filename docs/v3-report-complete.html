渐近线模型（数据可验）

macro_cost  = logic(op) × k − S      S ≈ 168 字符/op 的固定样板节省
inline_cost = logic(op) × k
ratio       = 1 − S / inline_cost

验算：inline 均 385、macro 均 217，差 168 → 1 − 168/385 = 0.56 ✓（实测 0.56）

抽象的收益不随 op 数量增长，随单个 op 的逻辑密度下降。适合大量薄逻辑（字段、路由、表单），不适合少量厚逻辑（算法、重排、冲突检测）。

04改：一条跨切规则（本轮真正的发现）

给已完成的 30-op 实现加 --dry 前缀（预演，不落盘，输出 n 但状态不变）。

臂改动位置Δchars做法
macro2+343分发层把状态动态绑定到一次性深拷贝，执行体照跑，结束丢弃副本 —— 30 个 op 与宏本体一行未改
inline30+56628 个会改状态的分支各加守卫 + 2 处共享骨架

两个必须记下的细节

  1. macro 的“一处”是环境替换，不是条件判断。它没在每个 op 里写 if dry，而是改了调用环境（动态绑定）。执行体根本不知道自己在预演。
  2. 两臂都不得不改同一处：argv 过滤。原实现丢弃以 - 开头的参数，而 --dry add ... 整条是一个以 - 打头的 argv 项，会被静默吞掉。抽象的“只改一处”有前提：输入层必须能把新语法送进来。

07理论修正 T1 / T1b

原 T1（隐含）：符号层价值 ∝ P（执行者错误率） × D（决定数）    ← 只算了收益

修正：
符号层净收益 = 收敛带来的节省（30–40% 字符 / 93% 改动位置）
             − 收敛带来的失效集中风险（从 ∏(1−pᵢ) 退化为 1−p_shared）

符号层改变的不是错误率的均值，是错误的相关结构 —— 从 15 个独立的错，变成 1 个共享的错。

T1b：抽象把 N 处检查收敛成 1 处；该处写对则全对，写漏则全漏。收益随 D 增长，风险随「该处被判据覆盖的程度」下降。推论：没有外部判据时，抽象的期望收益可能为负；有判据时为正。

09八条问题（全部定档，不修饰）

#问题严重后果 / 处理
1三批 op 难度被我排成递增（薄→厚）高Δ/op 绝对上升不能归因于方案；只有同批配对比值可用
2两臂起点不同源（macro 用修过一轮的 r3，inline 用一次过的 r1）高起点能力不等价，累计曲线不可比，「交叉点 N*」弃用
3每批 5 个 op 打包，n=1中拆不出单 op 成本，无区间
4增量与维护阶段零返工（9 批全一次全绿）高与建阶段 first_pass 0/3 vs 3/3 矛盾：抽象只在“第一次立结构”时更易漏
5判据与参考实现有循环风险中缓解：两臂独立实现亦通过；但同一 spec 的歧义可能三方同错
6最初只测“加 op”，未测“改共通规则”致命已补（§04）—— 补上后结论反转
7第一次测改动半径方法失效（纯追加 → hunk 恒为 1）中已改用「必须修改的既有代码处数」
8字符度量不含改动次数、认知负荷、阅读成本低用「改动位置数」部分弥补

这些脏数据为什么仍然有用

脏点它的用处
难度递增（1）正因为它单调，配对比值才成为唯一可信读数 —— 逼出了正确的比较口径
起点不同源（2）直接杀掉了「交叉点 N*」这个诱人结论，避免一个错误模型
零返工（4）最强反例信号：增量与维护比建更容易，所以“抽象更易漏”只发生在第一次立结构时
方法失效（7）换来更硬的指标：改动位置数，把 1.6× 变成 15×

11边界（不外推）

  1. 规模：只到 30 op；D 上千未测。
  2. 模型：单族、强模型一档；P>0 的一半未观测（C1）。
  3. 语言：只有 CL 与 JS 两种。
  4. 样本：建口径每格 n=3；增量 3 批 n=1；维护 n=1。
  5. 判据覆盖：56 条抓到的错已知，没抓到的错未知（C4 未收口）。
  6. 任务形状：换成需要 I/O 的任务可能翻盘 —— 旧数据正是反例。
  7. 改动位置数是「子代理自报 + 我核对」，不是机器精确计数。
