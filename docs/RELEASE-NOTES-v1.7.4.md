# RELEASE NOTES — v1.7.4（2026-11-02，勘误）

> 只做一件事：**更正 v1.7.3 里两个节省区间的上界。**
> **没有改动任何测量数字、判据或数据集——改的是「比值区间怎么换算成节省区间」这一步算术。**

---

## 错在哪

v1.7.3 写的 95% 区间：

```
CL  省 7%–29%
JS  省 7%–36%
```

**两个上界都错。**

---

## 真值

把比值区间反推成节省区间，要用 `省 = 1 − 1/比值`：

| 语言 | 比值区间（`v4-ratios.tsv`） | 节省区间 |
|---|---|---|
| Common Lisp | `[1.0771, 1.4423]` | `1 − 1/1.4423 = 30.7%` / `1 − 1/1.0771 = 7.2%` → **7.2%–30.7%** |
| JavaScript | `[1.0725, 1.3619]` | `1 − 1/1.3619 = 26.6%` / `1 − 1/1.0725 = 6.8%` → **6.8%–26.6%** |

---

## 为什么错得这么难看

`RELEASE-NOTES-v1.6.3.md` 里早就写着这两个数，而且专门警告过：

> 比值 1.2 的区间 `[1.077, 1.442]` 对应的省是 **7.2%–30.7%**（CL）与 **6.8%–26.6%**（JS）。上一版写「7–29%」是估的，现已改成 7%–30%。

v1.7.3 的「修正」做的是：**从 `B1-加n结果.md` 的表里抄了一行**，那张表没跟着 v1.6.3 改。抄完还在 JS 侧凭空加了个 36%。

**动作叫「去查表」，实际是「换一张表抄」，没做反推验算。**

---

## 这条错误的性质

不是判据错，不是数据错，是**算术步骤被跳过**：

> 比值区间和节省区间不是同一个东西。反推要做 `1 − 1/x`，端点顺序会翻过来。

`B1-加n结果.md` 里现在把推导过程写在表下面，下一个读者不必信端点，可以自己算。
