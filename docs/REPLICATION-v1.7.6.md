## 六、复核代理指出的四个问题（都已记进文档，没有辩护）

**① 覆盖数对变异体口径敏感。**
`trim` 做成「不改状态、n 恒 0」→ 红 `#18 #60 #75`（81/84）；做成「不改状态但保留计数」→ 只红 `#18`（83/84）。`clear` 同理：「不删但保留计数」红 `#20 #36 #59`；「连计数一起失效」多红 `#54`（80/84）。

**换个人造变异体，45 会变。** 这个数不是判据质量分。

**② `#60` `#75` 抓的不是 `trim` 的语义。**
它们是 `--dry trim`，比对的是报出来的 `n` 和被 dry 还原的状态。`trim` 方向改错（`to = tt` → `from = tt`）它们照样给 `ok trim 1`，所以 `trim-direction` 只红 `#18`。

**这两条判据覆盖的是「n 的书写与一致性」，不是 `trim` 语义。** 按行为归类会高估覆盖。

**③ `#36` 是万能网。**
`clear-noop`、`filter-count`、`count-fixed` 三个都红它（12 条命令的混合序列）。单看 `#36` 红不能定位问题，也不该被当成「这条判据有独立鉴别力」的证据。

**④ 「前 12 项覆盖 19 条」在任务书编号下不成立。**
按编号取前 12 项，实测并集 **18** 条。19 只在「去掉 `add-tofrom`、换上 `shift-direction`」这个分组下成立。属口径差，不是错算，但用原编号复现会得到 18。

## 八之补、第七步的复核（两轮，独立子代理）

第七步（发布元数据一致性）不是一次写对的。**每一轮都是盲跑子代理找到漏洞，不是自己复查找到的。**

| 轮 | 版本号检查 | 被什么骗过 |
|---|---|---|
| 第一版 | `String(desc).includes('v' + version)` | 把一处 `v1.7.6` 改成 `v1.7.60` → **PASS** |
| 第二版 | 边界正则 | ① 只改**第一处** → **PASS**（判据说的是「提到过」，不是「开头那句对了」）<br>② 两边 `version` 写短成 `1.7` → **PASS**（版本号当字面前缀拼进正则，`v1.7` 后面是 `.`，右边界成立） |
| 第三版 | 形态校验 + 提取比对 + 第一处必须对 | 见下面「已知不堵」 |

第三版的验证（主代理跑 + 子代理 `fb41aef0` 独立复跑，结论一致）：

| 测试 | 期望 | 实际 |
|---|---|---|
| 全部替换成 `v1.7.60` | FAIL | `FAIL ← description 里没有 v1.7.6；第一处是 v1.7.60` |
| 只改第一处 | FAIL | `FAIL ← description 第一处版本号是 v1.7.60` |
| 两边 `version=1.7` | FAIL | `FAIL ← version 不是三段式：1.7` |
| 两边 `version=01.7.6` | FAIL | `FAIL ← version 不是三段式或带前导零` |
| 作者顺序颠倒、集合相同 | PASS | PASS |
| 一方多一人 / 全部还原 | FAIL / PASS | FAIL / PASS，哈希逐字节一致 |

> 前导零那一行是子代理 `fb41aef0` 发现的：`^\d+\.\d+\.\d+$` 放行 `01.7.6`。改成 `^(0|[1-9]\d*)\.(0|[1-9]\d*)\.(0|[1-9]\d*)$` 后它 FAIL。

### 已知且**故意不堵**的两条（写进代码注释，不装作没有）

| 绕过 | 为什么不做 |
|---|---|
| `v1.7.6.1`、`v1.7.6x` 被抽成 `1.7.6` | 加 `(?![\d.])` 能堵，但会把 `v1.7.6.` 这种句末写法一起挡掉。句末句号是真实文本的常态，四段版本号不是 |
| 抽取跑在原始 HTML 上，`<span data-version="v1.7.6">` 也算一次出现 | 剥 HTML 需要解析器，而这条判据没有这个复杂度预算 |

判断依据：**这条判据要防的是「自己忘记改版本号」**（v1.7.5 那次就是），不是刻意构造。给不会自然发生的输入补判据，等于造假绿。

### 它还指出了第七步的根本边界

> 第七步**没有外部锚点**：不读 git tag、不读 Zenodo record id、不比 `date-released`。
> 所以两边一起停在旧版本号（都写 1.7.5），检查是绿的。

这条不打算在这一版解决——它需要接 Zenodo API 或 git，属于下一版的事。**记在这里，不假装没有。**
