> 起因：`deepseek-flash` / `deepseek-v4-pro` 两档都可调用，但**都不是 10B–30B**，B1 原始定义（中档执行者）在这把 key 上不可执行。

## 一、为什么不拿这笔钱去跑"小模型代理臂"

上一轮 `③` 的结论是：1.5B/3B 落在"完不成任务"一侧，测的是执行者资格。现在能买到的两档仍然在"强模型"这一侧，**同侧加钱不会产生左端点**。

能想到的三个"人工降容量"旋钮，逐一否掉：

| 旋钮 | 为什么不能用 |
|---|---|
| 压缩输出预算（max_tokens 卡死） | **与要测的变量共线**：CL 参考实现本来就比 JS 长，卡预算会机械惩罚长的那一侧，"抽象省字"变成"被截断" |
| 只给部分规格，逼执行者推断 | **改了任务**：不再是同一份冻结规格，36 条判据的前提不存在 |
| 不给判据反馈、单轮一次成功 | v3 本来就是这样（`first_pass` 即首轮），没有可降的空间 |

**结论：在这把 key 上，C1 仍然不可判。** 这一条要写进报告，不许用"跑了很多格"糊过去。

## 二、这笔钱买的那条 claim

现在 v3 的四个数字是**每格 n=3 的点估计**：

```
语言（同方案）  JS inline / CL inline = 0.97×      n=3 / n=3
语言（同方案）  JS table  / CL macro  = 0.81×      n=3 / n=3
方案（同语言）  CL inline / CL macro  = 1.39×      n=3 / n=3
方案（同语言）  JS inline / JS table  = 1.66×      n=3 / n=3
```

报告自己的边界写着：「每格 n=3，只够给方向，不够给区间」。

**要买的 claim**：

> **claim-9c（新）**：在固定规格、固定判据、单轮无反馈的条件下，
> 「同方案下 CL/JS 的**非空白非注释字符比**」的 95% bootstrap 区间**是否包含 1.0**。

- 若区间**不包含 1.0 且落在 1.0 之上** → 「语言不影响代码量」被反驳，方向反过来（CL 更省）。
- 若区间**包含 1.0** → 「语言不是变量」从"方向"升级为"带区间的结论"，且可以说清区间有多宽。
- 若区间**不包含 1.0 且落在 1.0 之下** → CL 更冗长，但那要能归因到哪一部分（生态 / 任务形状 / 方案），不能直接写成语言结论。

同一批数据另给两条：方案效应（CL 1.39×、JS 1.66×）的区间，以及两语言**方案效应是否同向**。

## 七、修订 A（2026-11-01，**跑满之前**写下；起因是冒烟格发现的判据分母陷阱）

## 八、修订 B（2026-11-01，跑满 6 格之后、23 格跑完之前；**只改口径描述，不改判据与指标**）

修订 A 把 37–56 那 20 条写成"跑完之后补的、未标定的扩展检查"。这个说法**不够重**，实测更严重：

- 判据 37–56 测的是 `swapTeacher` / `swapLoc` / `copyTo` / `truncate` / `keep` / `renameTeacher` / `dedupe` / `compress` / `compact` / `mirror` / `absorb` / `promote` / `purge` / `--dry` 这些命令；
- **`tasks/v3.spec.md` 里一条都没有**（v3 只有 15 个 op，见 spec §4）；
- `ref-js.js`、`ref-cl.lisp`（15-op 参考实现）也一条都没实现；只有 `ref-js-30.js` 实现了它们。

**结论：`check-v3.cjs` 一个文件里装了两个契约**——1–36 是 15-op v3，37–56 是 30-op 变体。对任何 15-op 实现，37–56 这 20 条**必然全红**，与实现好坏无关。

### 8.1 因此

| 项 | 结论 |
|---|---|
| 主结局口径 | `--upto 36` 不是"为了对齐 v3 而定"，而是**15-op 契约下唯一正确的分母** |
| `36/56` 这种读数 | 一律作废，不得出现在任何表里当质量指标（6/6 个 JS inline 格、v3 的旧产物，全是一样的 `36/56`） |
| 次要结局 | 取消。37–56 单列也没意义——它测的是另一个规格 |
| 已跑数据的处置 | 不受影响：生成与 chars 指标与判据无关，判定重跑 `--upto 36` 即可 |

### 8.2 一条要写进报告的方法学

**判据文件不标注它覆盖哪个契约，就会把"另一个契约的要求"变成"这个实现的缺陷"。** 这不是实现的问题，也不是模型的问题，是判据文件的作用域没写清。

修法（等 23 格跑完后执行，避免运行中改文件）：在 `check-v3.cjs` 头部注明两段判据的契约边界，并让不带 `--upto` 的调用直接报错退出，逼调用者显式声明分母。

## 九、修订 C（2026-11-01 14:2x，**看完第一轮失败之后**写下；这是本轮唯一的参数改动，也是最需要自曝的一处）

### 9.1 触发与原因

第一轮（`max_tokens=32768`）24 格里有 **6 格 `generation_failed`，全部在 CL 两臂**，且日志一致显示 `finish_reason=length`、`content` 为空、输出恰好等于上限。也就是说：

> **这 6 格不是"执行者做不出来"，是"工具把它的输出截断了"。**

这两件事在账上必须分开。截断属于**测量工具的上限**，不是被执行者的能力观测；把它算成 CL 的能力缺陷，就是拿工具错误去记模型的账。

### 9.2 决定

| 项 | 定 |
|---|---|
| 上限 | `max_tokens` 32768 → **65536**（已用一次 1 token 的探针确认该端点接受 65536） |
| 范围 | **CL 两臂全部 12 格重跑**，命名 `v5-cl-macro` / `v5-cl-inline`（不是只补那 6 格失败的） |
| 为什么不只补失败格 | 同一臂内混两种预算，等于把"预算"和"能力"混成一个变量。要么整臂同一预算，要么不做 |
| 第一轮处置 | `v4-cl-*` 12 格**原样留档**，不删、不改、不覆盖；报告里两轮都报 |
| 提示词 | 复用 `runs/prompts/v4-cl-macro.txt` / `v4-cl-inline.txt`，**字节不变**（哈希已在 `b1-prereg.sha256`） |
| 判据 | 不变：主结局 `--upto 36`；37–56 仍不作质量指标（见修订 B） |
| 指标 | 不变：`metric.cjs` 的非空白非注释字符 |

### 9.3 自曝（这段必须留在文件里）

这是**看过第一轮失败之后**才改的参数。它的合法性只建立在一条上：**失败原因是可核的截断，而不是可核的能力差异**（`finish=length` + `content` 为空 + 输出等于上限，三条同时成立）。

因此本修订附带三条硬约束：

1. **两轮都报**：报告里必须同时给"32768 轮"与"65536 轮"的 `generation_failed` 数与 `first_pass`，不许只报好看的那轮。
2. **同格对比优先**：若 v5 与 v4 在**同名格**上系统性不同（例如 v4 全崩、v5 全过），先怀疑**参数**，后怀疑模型能力——不许把它写成"CL 变强了"。
3. **不许反复试参数**：本轮只改这一次上限。若 65536 下 CL 仍有 ≥3 格 `finish=length`，**停止**，结论写"该模型在本任务上不足以稳定产出 CL 产物"，不再调第三次。

### 9.4 对主结论的影响（事前声明）

- `A（语言·inline）` 与 `D（方案·JS）` 的结论**不受影响**：它们的四个臂都已 n=6 完整，且 JS 侧 0 格失败。
- 若 v5 的 CL 两臂补满，则 `B（语言·抽象）` 与 `C（方案·CL）` 从"不可引用（幸存者偏差）"升级为"可引用"；升级的唯一条件是**该臂 6 格全部产出可判定产物**。
- 若只补到部分格，B、C 继续标"不可引用"，不许因为"样本变多了一点"就放宽。
