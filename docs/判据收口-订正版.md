## 二、先修前提：`claim-21` 的"不可再复现"是环境问题

`CLAIMS.md` claim-21 记：现跑 scale-lisp **0%（基线红，gate FAIL）**，与编年史 83.3% 对不上，按"不可判"处置。

原因一句话：**`check-scale.cjs` 只认 `SBCL` 环境变量或 PATH 里的 `sbcl`，本机 Windows 侧没有 SBCL → 36 条判据全部崩溃 → 基线全红 → `mutate.cjs` 的"引入新失败才算杀死"失去基准 → 得分 0%。**

同仓库的 `check-v3.cjs` / `check-v4.cjs` 早已支持 `SBCL_WSL=<distro>` 走 WSL，只有 `check-scale.cjs` 漏了这层。补上分派（+16 / −1 行，**只碰 run() 的分派，判据一条未动**，可用 `git diff` 核）：

```
$env:SBCL_WSL='kali-linux'
node check-scale.cjs --impl runs\scale-lisp\impl.lisp   → -- 36 passed, 0 failed
node check-scale.cjs --impl runs\scale-js\impl.js       → -- 36 passed, 0 failed
```

**基线恢复全绿，claim-21 关闭。** 这条本身是个可复用的教训：**工具链缺一层分派，会让"判据强度"这种二阶指标先塌，而塌的样子很像"结论错了"。**

## 三、变异得分（两臂，抽样 30）

| 臂 | 候选 | 抽样 | 可用 | 杀死 | 存活 | 得分 | 旧地板 | 新地板 |
|---|---|---|---|---|---|---|---|---|
| Common Lisp | 416 | 30 | 30（无效 0） | 25 | 5 | **83.3%** | 83.3 | 83.3 |
| JavaScript | 297 | 30 | 17（无效 **13**） | 12 | 5 | **70.6%** | 64.7 | **70.6 ↑** |

### 3.1 那 13 个"语法无效"是什么（逐条分类过）

全部出自同一个规则「删一行」，原因分布：

```
4 × Unexpected token ';'        删在语句中间
3 × Unexpected token '{'        删掉块的左括号行
2 × Unexpected token 'return'   删掉函数体唯一一行
2 × Unexpected token '}'        删掉收尾括号行
1 × Unexpected identifier 'a'
1 × Missing initializer in const declaration
```

**没有一个是比较符翻转或常量替换造成的。** 旧结论继续成立：这是**变异器的几何粗糙**，不是"JS 更抗改"。要修得让删行规则懂 AST 边界，不是正则。

### 3.2 两臂得分不能比大小（新增边界）

| 臂 | 得分 | 可用变异 | 每杀一个 = | Wilson 95% CI |
|---|---|---|---|---|
| CL | 83.3% | 30 | 3.3 个百分点 | **[66.4%, 92.7%]** |
| JS | 70.6% | 17 | 5.9 个百分点 | **[46.9%, 86.7%]** |

区间重叠一大半。**"CL 的判据比 JS 严"在数据上不成立。** 以前把 83.3% / 64.7% 并排写，读起来像"CL 强 18 个点"，那是不成立的读法。正确写法：**两臂判据强度同档，不可排序**；要排序得先把 JS 可用样本提到 30（修删行规则），或改成配对设计。

### 3.3 地板与门禁的两个坑（复核人查出，已修）

- **64.7 复原不了**：三个检查点（判据 26 条 52.9%、30 条 58.8%、36 条 70.6%）都算不出 64.7，旧地板没记判据集 hash。按现判据集重设为 70.6，并在 `mutation-floors.json` 里留档说明。
- **`gate.cjs` 默认 `--max 40`**，而地板是按抽样 30 记的 → 不带参数跑 gate 时 JS 只有 60.0 < 64.7，**会误报 FAIL**。已改为默认读 `mutation-floors.json` 的 `sample` 字段。

## 五、K1–K7（`check-closure.cjs`）

每条都指得到 spec 原文；指不到的不写——这是 #32/#36 撤回换来的纪律。

| 判据 | 断言 | spec 依据 | 杀掉 |
|---|---|---|---|
| **K1** `add-tag-roundtrip` | add 给的 tag 必须保留；没给的必须是 null 或省略 | L15「`tag`：字符串或 `null`（可选字段，缺省 `null`）」 | js-L30 |
| **K2** `trim-to-single-slot` | 3..5 收窄到 [5,7] → 5..5 且 n=1 | L46「把命中课的节次范围收窄到 `[from,to]`」 | js-L157 |
| **K3** `untag-count` | 两门同标签 → n=2；两门不再带 `'x'`（**允许 null 或省略**）；第三门不动 | L26「`n` = 实际改动条数」＋ L50「删掉所有该标签」 | js-L216 |
| **K4** `location-roundtrip` | add 给的 location 留住；edit 没提到它时不许抹掉 | L9 数据模型 ＋ L36「只改 `set` 里的键」 | cl-L200 |
| **K5** `add-keeps-period-from` | add periodFrom=3/periodTo=4 → 原样 3..4 | **L34** add 行只列了两处改写（缺 weeks→默认、day 夹 1..7），未授权改节次 | cl-L282 |
| **K6** `move-periods-landed` | move 到 day=3 / 3..4 → 必须**等于参数**且 n=1 | L37「`move` … 三件套」 | js-L99 |
| **K7** `shift-clamp-min1` | `shift(1..2, -3)` → 只查 `periodFrom ≥ 1` 且 `periodTo ≥ periodFrom` | L48「夹在 ≥1，`periodTo ≥ periodFrom`」 | js-L187、cl-L380 |

### 5.1 三个"不咬实现"的证据

1. **两个基线实现全绿**：JS `7/7`、Lisp `7/7`。
2. **一个合法变体全绿**：复核人造的「tag 为空则省略键 + untag 用 delete」实现，36 条全绿、K1–K7 全绿。（这一条是 K3 从"必须 null"放宽到"不再是原值"的由来。）
3. **4 条非盲区变异在补丁下仍全绿**：若补丁判据在咬实现偏好，这 4 条会假红，现在没有。

### 5.2 K7 只查"不倒挂、不越界"，不规定落点

夹紧策略可以不同（夹到 1..1、1..2、1..3 都算合法），所以 K7 不断言具体值。这条是复核人反复强调的点：**断言过分具体，杀死的不是错误，是另一种写法。**

### 5.3 门禁的洞：K1–K7 一度没人守（实施员自己报的，已补）

第一轮实施员在"按清单没动但可疑"里自己报了一条，主代理看源码确认：

```
gate.cjs  →  mutate.cjs  →  只 spawn check-scale.cjs
```

也就是说：**把 `check-closure.cjs` 整个删掉，`gate.cjs` 照样 PASS。** 新增的 7 条判据没有任何回归保护——这比"判据不够多"更危险，因为判据会悄悄消失而门禁继续绿。

修法（第二轮实施）：`gate.cjs` 增加一步——对 `floors` 里每个实现跑 `check-closure`，要求 `7 passed, 0 failed`；并校验 `closure-matrix.tsv` 的 sha256 与 `closure-matrix.sha256` 一致（证据表被改过但没重新存证 → 计 FAIL）。另加 `--closure-only` 快速开关，让这项检查能在 30 秒内跑完，而不是每次等 9 分钟变异。

验收用的是**篡改测试**，不是"跑一遍绿了就算"。主代理在 `tmp/gate-tamper/` 里复制了一份门禁（不碰真实目录），然后拆它：

| 场景 | 期望 | 实测 |
|---|---|---|
| A 副本原样 | PASS | **exit 0**（3.8 s） |
| B 删掉 `check-closure.cjs` | FAIL | **exit 1**（2 项未通过） |
| C 往 `closure-matrix.tsv` 追加一个字符 | FAIL | **exit 1**（存证不符） |
| D 把实现换成会红 K1 的 `js-L30.js` | FAIL | **exit 1**（补丁判据未全绿） |

四个场景全部按预期。**门禁现在真的会为"判据消失"和"证据被改"失败**，而不再只是"跑绿了"。

### 5.3b 第三轮：把三种"静默放行"也堵上（含主代理第二套篡改）

第二轮实施员又报了三条同类缺口，全是"该 FAIL 却 PASS"：`criteria_sha256` 只登记不校验；K1–K7 的覆盖面绑在 `floors` 的键上（删一条 floor 就把守护一起删掉）；实现文件挪走后打印 `[skip]` 然后 PASS。

### 5.4 仍然存在的五个边界（写清，别让下一版当它们不存在）

| # | 边界 | 影响 |
|---|---|---|
| 1 | `sample: 30` 但两臂**可用变异数不同**（Lisp 30/30，JS 17/30，13 个删行变体语法无效） | 83.3%(25/30) 与 70.6%(12/17) 分母不同，**得分不可排序**（Wilson 区间重叠，见 §3.2） |
