符号层的第二次机会：一个可被推翻的测量

许宸玮 · 北华大学文学院 · 2026-10 · 附数据集 DOI：10.5281/zenodo.23618044（concept DOI，永远指向最新版）· 含数据表，共 2 页

一句话

1988 年爱丁堡给出的判断是「原始数据完美地转换成符号是不可能的」，符号路线因此被判死。今天这一步被模型做掉了——所以符号层第一次可以被单独拿出来量。量出来的结果是：它还在，但它只在执行者会犯错的时候兑现。

命题

① 原始数据 → 符号　　—　他说：不可能。符号路线死。
② 符号 → 可执行　　　—　他没说，因为 ① 已经判死。
本文只做 ②：在 ① 由模型完成之后，符号层剩多少。

方法（预注册，跑完不许改）

  • 同一份需求书、同一套判据；每条判据先证明它会报错，才允许它说「通过」。
  • 十几个互相看不见彼此实现的 agent，分别用 Common Lisp / JS / Java / Rust / Julia 写同一件事。
  • 主指标事后改口径：物理行数 → 非空白非注释字符（原因见下表第一行）。
  • 负结果全部保留，不删；错误记录 15 次全部在案。

只有符号层能做的两件事

能力实测
展开期拒绝同一缺陷：关校验 19/19 判据全绿；开校验加载即失败。入口对比：compile-file 一次点名 3/3，--script 1/3，node --check / py_compile 0/3。
看见 body 内部宏可在展开期统一收口写入点，算出「本次改了什么」；其他写法必须手写声明表。
其余七条常见杠杆测不出。另：「立刻响」最强的不是 Lisp，是 g++；Lisp 只是默认开着。

一个公式

一条缺陷的期望成本 = P(该执行者写出来) × 发现时延
静态检查省下的成本 ∝ 执行者的错误率 P。
九条杠杆里七条作用于「降低错误」；在 P≈0 的执行者身上，七条全部测不出来。

所以本轮的结论不是「Lisp 有没有优势」，而是：符号层的价值 ∝ 执行者的错误率。1988 年它没赚到钱，因为转换做不出来；今天它没赚到钱，因为错误不够多。同一个位置的同一笔账，赤字的原因完全相反。

我缺什么（一个可证伪预测）

所有成本类结论都受「模型熟练度」污染：本轮用的是强模型，返工轮数被压到 10/10 = 1 轮、方差只落在时钟上。可证伪预测：换高幻觉的小模型重跑，若返工轮数仍拉不开，上述结论作废。缺的只是算力——一张卡、几个小时。
