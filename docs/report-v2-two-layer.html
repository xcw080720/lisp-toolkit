三个可写进论文的观察

  1. 一处宏错 → 31 条判据全崩。不是 31 个错，是同一个错被 31 条判据各撞了一次。
  2. 一处修复 → 28 条判据恢复，代价 35 字符。修好与修坏走同一条路径。
  3. 剩下的错仍同时压着 2 个 op。duplicate 与 copy 共用同一个复制调用点。

对照：同批 inline 臂首次即 36/36、返工 0 次。这是"收敛换来代码量、同时换来失效集中"的第一个干净样本（n=1）。

A4本层能说 / 不能说

能说不能说
四格证据链完整，可被第三方复核不能说概率（每格 n=1，无区间、无显著性）
字符口径下语言效应小、方案效应大不能说"宏更容易出错"（1 次 macro 失败、1 次 inline 全绿，n=1 不构成频率）
宏臂出现单点失效扩散（一处压 31 条，后一处压 2 条）不能外推到 30 op 与维护臂（本层只覆盖 op 1–15）
判据与实现可同向读漏，此时自检无效（E-04 实证）不能说「判据全绿 = 实现对」——它只证明「实现符合判据作者的理解」
