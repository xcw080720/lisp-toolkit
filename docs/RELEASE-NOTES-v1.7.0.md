# RELEASE NOTES — v1.7.0（2026-11-01）

> 这一版不动任何已有数字（字符比、维护半径、通过率全部不变）。
> 它做的是：**把判据的射程画出来，并标出射程外有什么。**

## 零、先说坏消息

按「红了是好消息、按部就班是坏消息」的记法，本版找到五条坏消息。

### 坏消息 1：36 条判据对这批变异体的杀伤力是 **0 / 12**

| 判据集 | 12 只变异体中抓到 |
|---|---|
| `check-scale.cjs`（36 条） | **0 只** |
| `check-closure.cjs`（K1–K7） | **8 只** |

而回归门禁（`gate.cjs`）**只跑 `check-scale`**。真正有杀伤力的那 7 条，不在门禁射程内。

### 坏消息 2：`check-closure.cjs` 对 v3-full 零判别力

K1–K7 测的是 `scale.spec` 的 JSON 契约。在 v3-full 的 10 格上**基线也是 0/7**（`stdout 非 JSON`）。

所以「87 条判据」这个说法不成立。正确的是 **84 + 2 + 2 = 88 条**。

### 坏消息 3：JSON 序列化保真度整块无人约束

整套内容判据都在 `JSON.parse(stdout)` **之后**断言。唯一涉及 `opsText` 的是 `o.opsText === ''`。

**后果**：值对了就算对，"这个值怎么写的"完全不受约束。`cl-L127` 是活证据——所有 ASCII 空格转义成 `\u0020`，解析后每个字段全等。

**这是规格缺口，不是判据缺口。** spec 里没有一条说"ASCII 可打印字符不得转义"。想管得先加规格，否则补判据等于给规格追加未声明的约束。

### 坏消息 4：`swapDays` 的 CONFLICT 是不可达分支

7 组对抗输入下，删掉整段冲突检查与基线**逐字节相同**（换日标签保持"天内无重叠"不变量）。**给它补判据等于造一个假的绿**，只能登记。

### 坏消息 5：20 个绿 = 零信息量

10 格 × 4 条新判据（H1/H2/S1/S2）= 20 个绿。**这只说明这批实现没踩这两条线，不说明判据强。** 它们的判别力靠反例证明，不靠这些绿。

## 一、这一版做了什么

### 1.1 判据工程的三个方向

| 方向 | 问题 | 手段 | 本轮产出 |
|---|---|---|---|
| ① 规格 → 判据 | 规格写了，判据覆盖吗？ | `SPEC-AUDIT.md` 核对表 | ❌ 缺口 2 → **0** |
| ② 判据 → 实现 | 实现错了，判据会红吗？ | 变异测试 12 只 | 8 杀 4 活，A 类 0 |
| ③ 判据 → 判据 | 判据自己会红吗？ | 反例验证 **8 条** | **8 条全红** |

七次判据错误按方向分类：

| 类 | 错在哪 | 靠什么发现 |
|---|---|---|
| A | 期望值算错（错误 1–5） | **跑一遍** |
| B | 读漏规格（错误 6，E-04） | **逐条对读** |
| C | 检查方法比规格窄（错误 7） | **造反例** |

### 1.2 新增 8 条判据，每条都经反例验证

| 判据 | 文件 | spec 依据 | 反例 | 结果 |
|---|---|---|---|---|
| `#83` copyTo 撞已占时段 → CONFLICT | check-v4 | L162 | 删冲突检查 | **红**，并暴露"部分生效" |
| `#84` copyTo 自撞 → CONFLICT | check-v4 | L162 | 同上 | **红** |
| `#85` n ≥ 4 | check-v4 | L39 | n 补两位 | **红**（`ok purge 04`） |
| `#86` copyTo 撞名 → DUP | check-v4 | L161 | 删 copyTo 查重 | **红**，变异体真多写了一门重名课 |
| `H1` 行尾 + **行首**空白 | check-hygiene | L61 | 尾空格 / NBSP / 行首空格 | **三红** |
| `H2` 不依赖 cwd | check-hygiene | L124 | 输出拼 `process.cwd()` | **红** |
| `S1` 禁文件 IO | check-static | L94 | `require('fs')` + 读文件 | **红** |
| `S2` 禁 JSON | check-static | L95 | 加 `JSON.parse` | **红** |

### 1.3 三个「输出层面完全不可见」的反例

最强的一组证据：

| 反例 | `check-v4` 分数 | 抓它的判据 |
|---|---|---|
| 行首加空格 | **78/84（基线，看不见）** | `H1`（`LEADING_WS`） |
| `require('fs')` 读文件 | **78/84（看不见）** | `S1` |
| 加一行 `JSON.parse` | **78/84（看不见）** | `S2` |

**三个变异体的 stdout 与原版逐字节相同，84 条内容判据一条没动，只有新增的判据集能抓。**

### 1.4 `H1` 曾有自己的盲区

第一版 `H1` 用 `/[ \t]$/`，对 **NBSP（U+00A0，`C2 A0`）** 尾空完全漏检；而且**只查行尾**——`check-v4` 的 `trim()` 会吃掉行首，两边同时失明。

现在：`\s` + 字节白名单（`0x20 / 0x09 / C2A0 / E38080`），并且行首行尾都查。

### 1.5 `SPEC-AUDIT.md`

16 行核对表：13 ✅ / 3 ⚠️ / **0 ❌**。它抓到过五次「实现本来对、但此前完全不受约束」。

### 1.6 C4 变异审计

12 只：**8 杀 4 活**。存活全部分类：

| 变异体 | 类 | 依据 |
|---|---|---|
| `cl-L127` | C 越界 | 只改 U+0020 转义形式（见坏消息 3） |
| `cl-L427` | B 等价 | `and`→`or` 只在 msg 为 `""`/`nil` 时分叉；15 个 op 的 msg 全非空 |
| `cl-L444` | B 等价 | 删掉的 `(finish-output)` 是加载期顶层表单，早于 `(main)` |
| `js-L1` | B 等价 | 删 `'use strict'`；无严格模式敏感构造 |

**A 类（真盲区）= 0。** 8 只该抓的全抓到，4 只没抓到的不该抓。

**另注**：存活 4 只恰好是 `gen-closure-mutants.cjs` 里 `key:null` 的那 4 只——是覆盖缺口，不是抖动。

### 一个复核时发现的文档缺陷

`check-v4.cjs` 的编号是 `1–80, 83–86`，**81/82 是空号**（对应 hygiene 的 H1/H2）。盲跑时确有子代理据「编号到 #86、分母 84」误推为「实际跑了 86 条」。

## 三、这一版没做什么

- 没把 K1–K7 装进 gate（坏消息 1 的修法）
- 没给 spec 加「不得转义 ASCII」那一行（坏消息 3 的修法）
- 没给 3 条 ⚠️ 弱覆盖全部补判据（已攻击，见 `ATTACK-WEAK-COVERAGE.md`）
- 没扩大变异样本（仍 12 只）
- 没对剩下 76 条判据造反例（只对新增 8 条做了）
- 没换模型、任务、规格

**六条"没做"全部可指名，不是被忘记。**
