# RELEASE NOTES — v1.6.3（2026-11-01，纯文档）

> 只做一件事：**给每个区间标上它是从哪一次重采样里来的。**

## 为什么

同一条比值，用不同的随机种子做 bootstrap，点估计一模一样，但区间端点会在第三位小数上动
（语言·inline 的下界在 0.825–0.829 之间）。之前正文只写端点、没写种子，导致：

- 信里写 0.83，文档里写 0.825，两边都对，但读者会以为其中一个错了；
- 复现的人换种子跑出 0.829，会怀疑自己跑错。

## 改了什么

| 位置 | 改动 |
|---|---|
| `experiments/timetable-ab/v4-ratios.tsv` | 首两行记录口径：`seed=20261101`、`iters=20000`，并说明换种子的变动幅度 |
| `docs/B1-加n结果.md` / `reports/B1-加n结果` | 新增「§2.0 区间口径」，正文端点统一为 seed=20261101 |
| `README.md`、`docs/RELEASE-NOTES-v1.6.0/1.6.2.md`、`docs/knock.md`、`docs/v3-report.md` | 端点由 0.825 统一为 **0.829** |
| 致西湖更正信（11-02 发送版） | 区间写成 0.83–1.12 / 0.88–1.10；「省」的区间改为 7%–30%（由比值区间反推，不是直接读端点） |

## 一个副产品

反推「省多少」必须换算，不能直接读比值端点：比值 1.2 的区间 [1.077, 1.442] 对应的省是
**7.2%–30.7%**（CL）与 **6.8%–26.6%**（JS）。上一版写「7–29%」是估的，现已改成 7%–30%。
