# PAPER OUTLINE —— 静态检查的价值随执行者错误率变化

> 状态：骨架（2026-10-24）。已有单模型证据，缺多模型族。
> 所有数字来自 `experiments/timetable-ab/`，可复算。

---

## 0. 一句话

> **"哪种语言/抽象更省"这个结论，会随执行者的错误率 \(P\) 翻转；
> 而现有 LLM 编程基准几乎都不报 \(P\)，所以它们的结论互相矛盾。**

## 2. 现有文献的问题（要讲得具体，不能泛泛）

现有 LLM 编程基准（HumanEval 一类、仓库级任务、语言横评）有三个共同缺陷：

```
① 只报语言/抽象，不报执行者的错误率 P
   → 结论不可迁移：换模型可能翻转，但读者看不出来

② 因变量多是"一次通过率"或"代码行数"
   → 一次通过率在强模型上是天花板（接近 1），失去区分度
   → 行数不是语言属性，是排版属性（本文有实测）

③ 不区分缺陷的可见性层级
   → 把"编译期就报"和"永远不报"混成一个数字（缺陷率）
```

**第 ③ 条是本文的核心切口。**

---

## 3. 框架

### 3.1 缺陷的三层可见性

| 层 | 定义 | 发现时延 |
|---|---|---|
| **① 立刻响** | 写下去就被点名，没跑就知道 | ≈ 0 |
| **② 迟早响** | 跑到那条路径才炸 | ≈ 1 轮 |
| **③ 永远不响** | 跑得起来、结果错、测试不覆盖 | ∞ |

**关键**：语言/工具链的差别不在"能不能发现"，在**"把哪些缺陷放在哪一层"**。

### 3.2 公式

\[
\text{期望成本} = \sum_{\text{缺陷类型}} P(\text{该执行者写出它}) \times \text{发现时延}(\text{它落在哪一层})
\]

静态检查的收益：

\[
\Delta = \sum_{\text{可提升类型}} P \times (\text{原时延} - 0) \quad \propto \quad P
\]

**所以 \(P \to 0\) 时，任何"降低错误"的干预（文档、静态检查、更强的抽象）收益都趋近于零。**

### 3.3 天花板效应

> 用低错误率模型做的语言对比，**测到的是地板，不是语言**。
>
> 零返工不是好结果，是坏信号：它说明这次实验没有信息量。

## 4. 已有证据（单模型，强度标注）

| 证据 | 数字 | 强度 |
|---|---|---|
| 同一缺陷，四种入口各能点名几处 | CL `compile-file` **3/3**；CL `--script` **1/3**；JS `node --check` **0/3**；PY `py_compile` **0/3** | **强**（工具链性质，可复算） |
| ①层实例 | CL `compile-file` 一次列全并给 `caught 4 STYLE-WARNING` | 强 |
| ②层实例 | JS 未定义函数：`node --check` 报 0，运行到才 `ReferenceError` | 强 |
| ③层实例 | JS `periodTo = max(from+1,…)` 种进去后**判据全绿** | **强**（我种了，没人发现） |
| ③层实例 | 判据自身假阳：`#4 del-miss` 只看长度，空数组恰好补上长度 | 强 |
| 行数指标失效 | 同一份代码：物理行差 **4.05×**，非空白字符差 **7.6%** | 强 |
| 六语言体积（5 op，非空白非注释字符） | PY 4750 / JS 5933 / Java 6970 / Julia 7316 / CL 7506 / Rust 9390 | 中（n=1/语言） |
| 返工轮数（同一模型，6+6 臂） | 0–4 轮，中位 1；零返工占 2/12 | 中（n 小） |
| 技能包干预 | A/B 各 3 run，**无可测效应**；两臂边界错误均 0/3 | 中（n=3） |
| 六个"单缺陷病人" | 全部一处一行、一次改对、零试错；red→root 5–30 s，区间重叠 | 中（说明 P 低） |

**这一栏的力量在于第 1 行和第 4 行**：一个是工具链的确定性质，一个是"静默失败"的实物。

## 5. 缺失的证据（必须补，否则不能投）

```
① 多模型族  ← 致命
   同一个家族 3 个规模档（7B / 27B / 70B）+ 另一个家族 1 档做家族对照
   目的：让 P 跨越量级，看 Δ 是否随 P 增长

② n ≥ 5
   现在多数格子 n=1；返工轮数需要分布而不是单点

③ 断网
   砍掉"检索"这个混淆项；审稿人一定会问

④ 工具链对齐
   JS/Python 加装 eslint / pyflakes 之后，①层的差距还剩多少？
   —— 这是"语言本体优势"与"默认配置优势"的分界线，必须测
```

## 6. 预注册设计（写死，跑完不改）

### 6.1 主实验：P × 语言 × 缺陷类型

```
任务：同一份中等规格（15–30 op，含 2 种形状）
因子：执行者 P（3 档）× 语言（CL / JS）× 缺陷类型（①②③ 各一）
每格 n = 5
因变量：
  主  返工轮数
  主  每轮修好几处
  主  ②③ 层缺陷占比
  副  ①层诊断条数（编译器/解析器一次给出几条）
```

### 6.2 主结局的定义方式（今天踩过的坑）

```
✗ 不许用「某种报错文本出现与否」定义结局
✓ 必须用「客观行为测试」定义：同一条断言在"真实现"上绿、在"未实现"上红
```

今天因此错过一次：把"边界类错误"定义成 grep 一个报错字符串，漏掉了静默塌缩的那一半。

### 6.3 种点验证（今天踩过三次）

```
每一个植入的缺陷必须证明三件事：
  ① 它确实命中（字符串替换真的发生了）
  ② 它确实红（判据失败）
  ③ **它红的理由就是我以为的那个**（隔离测试：单独种一处，看是不是预期的那条断言）
```

第 ③ 条是新的——今天三次种下去的是语义空操作，其中一次（CL 末尾括号）**真错了但发生在输出之后，对外不可观测**。

### 6.4 难度下限

```
每一格必须让最强模型也产生 ≥1 次返工，否则降低任务规格
理由：见 §3.3 天花板效应
```

## 7. 威胁效度

| 威胁 | 处理 |
|---|---|
| 模型能力与家族混淆 | 同家族 3 档 + 另一家族 1 档 |
| 作者方差 > 干预效应 | 每格 n ≥ 5，报分布不报均值 |
| 工具链差异冒充语言差异 | §5④ 的 linter 对照 |
| 任务太小，规模效应没显现 | 任务推到 15–30 op；并声明规模边界 |
| 判据自身假阳 | 每次跑变异测试，报变异得分；基线必须绿 |
| 我们自己会犯错 | **保留全部自我推翻记录**（今天 19 次），逐条列出 |

**最后一条是本文的特色**：这类论文通常只报"我们设计多严谨"，本文报"我们的测量工具错了 19 次，以及每次怎么发现的"。

## 8. 可证伪预测（写死）

```
换高错误率执行者（Seed / Gemini 这一栏）重跑：
  ① 返工轮数从 0–1 拉大到 2–5
  ② ②③ 层缺陷占比上升
  ③ CL 的「提前响」变成可见的时间差

若换模型后轮数仍拉不开 → 本文理论被证伪，应撤回
```
