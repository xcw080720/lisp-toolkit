## 3. B 组：20 条锐判据（`check-v4.cjs` 57–76）

设计原则：专打"看起来对但没做对"的地方——**n 一致性、原子性、幂等性、dry 与真实执行等价**。

| # | 类型 | 内容 |
|---|---|---|
| 57 | dry 等价 | dry 遇冲突也要报 CONFLICT |
| 58–64 | **n 一致性** | dry 报的 n 必须等于真实执行的 n（del/clear/trim/shift/compress/dedupe/purge） |
| 65 | 状态隔离 | 连续 dry 不累积改状态 |
| 66–67 | dry 等价 | dry 遇 DUP / BADARG 照旧报错 |
| 68–69 | **原子性** | shift 越界不得部分生效；mirror 撞名不得复制任何一门 |
| 70–71 | **幂等性** | 第二次 dedupe / compact 必须为 0 |
| 72–74 | 顺序与边界 | shift 两次等于 +2；名字 13 字符越界；跨天同时间段可重叠 |
| 75 | 语义结构 | `trim` 只截跨过 to 的门（**n 结构上 ≤ 1**） |
| 76 | 混合 | dry 与真执行混用仍正确 |

### 结果

| 格 | 57–76 |
|---|---|
| full-cl-macro / full-cl-inline / full-js-table / full-js-inline | **全部 20 / 20** |

### 但这一节的真正价值是我的四次错误

| # | 我写的 | 真相 |
|---|---|---|
| 61、72 | `shift 1` | `shift` 是 **`day delta` 两个参数** |
| 76 | `move a 2` | `move` 是 **`name day from to` 四个参数** |
| 75 | 期望 `trim` n=2 | `add b` 与 `a` 冲突没进去；且 **`trim` 的 n 结构上最多为 1** |

**四次错，一个盲区**：忘参数签名、忘 `add` 会查冲突、没想到语义的结构性上限。

而**四个独立实现都没犯这些错**。所以判据自审的方法要改：

## 4. C 组：加一条全局规则的成本（本版核心，可核）

设计：先拿到"30 op 但不含 `--dry`"的实现（判据 1–51 全绿），**只给规则、不给位置**，再量改动。

| 指标 | macro | inline | 比 |
|---|---|---|---|
| **op 层改动** | **0 处** | **28 处** | **0 : 28** |
| argv 过滤 | 1 | 1 | 1 : 1 |
| 剥前缀 / 报 verb 名 | 1 | 1 | 1 : 1 |
| **合计结构接触点** | **2** | **30** | — |
| 被改写既有行 | **3** | **439** | **146 : 1** |
| 改动块（hunk） | **4** | **34** | 8.5 : 1 |
| Δ 非空白字符 | +292（8750→9042） | +514（10487→11001） | 0.57 |
| 判据（76 条） | 76 / 76 | 76 / 76 | 打平 |

### 4.1 两处接触点是共享的

**argv 过滤与"报自己的命令名"这两处，两臂都必须改。** 差别只在 28 个 op 上。

准确表述：不是"macro 只要改 1 处"，而是**驱动层 2 个结构点必改（与 inline 相同），op 层 0 处（inline 是 28 处）**。

### 4.2 macro 的做法：环境替换，不是条件判断

```
(if dry-p
    (let ((*tt-db* (mapcar #'copy-course *tt-db*)))
      (tt-dispatch verb args))     ; ← 同一个分发函数，op 不知道自己被预演
    (tt-dispatch verb args))
```

返回的 `n` 天然是"将会影响的数量"；出错时 `throw` 穿过动态绑定——**既不留痕，也不吞错，连 `unwind-protect` 都省了**。

### 4.3 inline 的做法：逐点内嵌

28 个会改状态的分支各包一层 `(unless dry ...)`，`n` 的计数留在守卫外。**每处都只多一层，没有一处要重写控制流**——但确实是 28 个必须想清楚的地方。

### 4.4 附带证据：38 例差分自测

每个 op 各 1–2 条，验证 `--dry <cmd>` 报的 `n` 与真实执行**逐字一致**，且 dry 后 `#state` 与"只跑 setup"**逐字节相同**，mismatches = 0。

### 4.5 「op 层 0 处」有两条前提（必须写清，否则这个数被高估）

**前提 1：argv 预过滤必须认得出这条前缀。**
原实现"以 `-` 开头即当开关丢弃"，`--dry add a t r 1 1 2` 整行在分词之前就没了。所以**驱动层的第 1 处（argv 谓词）是任何方案都躲不掉的**，与 op 无关。

**前提 2：状态必须是可整体重绑定的单一根，且内部无嵌套可变槽。**
这里状态是 `*tt-db*`，`course` 是扁平结构体，`copy-course` 就够"深"。如果换成"多个全局变量"或"`setf` 原地改字段"的写法，光换绑定截不住 `(setf (course-teacher c) ...)` 这类就地写，**macro 也得逐点改**。

> 所以准确表述是：**收敛让"一处改全部"成为可能，但前提是状态被组织成一个可替换的根。**
> 这个前提是本任务的设计给的，不是抽象自动带来的。

| **本版（可核）** | 30 : 3 = **0.10** | ✓ |

## 6. 理论：T1b 改写成「符号化风险」

```
旧：净收益 = 节省 − 失效集中风险          风险是抽象固有的，无解
新：净收益 = 节省 − 符号化风险 × (1 − 是否会查符号)
```

**机制**：抽象把"名字"提升成"符号"。符号有命名空间，而命名空间与语言自带的那一套重叠。名字空间冲突**读代码看不出来，只能查符号**。

| 执行者 | 风险 |
|---|---|
| 会查（`find-symbol` / `compile-file` / `macroexpand`） | ≈ 0（一行 `defpackage` 解决） |
| 不会查（盲修） | 100%，且是**全崩**（编译期全局失败） |

这也把悬了很久的 **C1（弱执行者）** 具体化了：**弱不是逻辑差，是不会用语言自己的检查手段。**

## 附录 A. D1 实验：自检 vs 禁自检（D1 偏差的正式补救）

同一规格（`v3-full.spec.md`，sha `b202981a…`）、同一判据（76 条）、同一模型族。**唯一变量是检查协议**：

- **A 组（禁）**：写完直接交付，不许编译、不许运行、不许自测
- **B 组（允许）**：允许并鼓励 `compile-file` / `find-symbol` / `macroexpand` / 实跑

每格 `prompt.txt` 逐格落盘，协议段文字不同、其余逐字相同。

### A.1 结果

| 格 | 协议 | chars | 判据 76 | 自检强度（自报） |
|---|---|---|---|---|
| d1-nocheck-macro-1 | 禁 | 9753 | **0 / 76** | 0 次（如约不编译、不运行） |
| d1-check-macro-1 | 允许 | 9077 | **70 / 76** | compile×6 + 实跑 ~320 + find-symbol 扫 61 名 + macroexpand + **149 条自建用例** |
| **d1-check-macro-2** | 允许 | 10814 | **76 / 76** | compile×5 + find-symbol 扫 60 名 + 实跑 ~180 |
| d1-check-inline-1 | 允许 | 10440 | **76 / 76** | compile×3 + 实跑 ~180 |

### A.2 四个观察

**（1）自检把「全崩」变成「选择性失败」。**
禁自检的 macro 编译期即崩（0/76）；允许自检后变成 76 与 70——**错误从"全局不可用"降级为"局部偏差"**。

**（2）自检能查符号，不能查理解。**
`d1-check-macro-2` 用 `find-symbol` 一次扫 60 个自用名，**在编译之前就查出 `SIGNED` 撞 `SB-ALIEN`** 并改名。这是同像性最直接的收益：不用等编译器崩。

但它同样**没能**发现 D5（驼峰歧义）——因为它自己理解的规格就是"保留驼峰"。而 `d1-check-macro-1` 理解的规格是"归一化小写"。

> **自检消除实现偏差，消除不了理解偏差。**
> 前者靠查符号/跑一遍就能抓；后者只能靠外部判据。

**（3）自检强度与结果没有单调关系。**

`d1-check-macro-1` 的自检动作**比 `d1-check-macro-2` 更多**：编译 6 次 vs 5 次、实跑约 320 次 vs 180 次、还多出 149 条自建用例（79 主 + 31 边界 + 39 fuzz）且全绿。

**它的成绩却更差（70 vs 76）**，挂掉的 6 条全落在同一个判断上：

> 它明确写下——“verb 输出取命令名小写 → `swapTeacher` 输出 `ok swapteacher 2`，输入大小写均接受”。

而 `d1-check-macro-2` 写下的是相反的判断（保留驼峰、输入用 `string-equal` 不敏感）。

所以：

> **自检的上限不是工具的质量，是你自己判据的质量。**
> 149 条自建用例全绿，只证明了“实现符合我的理解”，没有证明“我的理解对”。

这一条比“自检修好了实现层错误”更重要——它给“同像性值多少钱”划了上界：**工具能让你自己一致，外部判据才能让你正确。**

**（4）同一份规格，两格 macro 读出相反答案。**
`d1-check-macro-2` 明确写下判断："输出 verb 沿用规格表原拼写，输入匹配用 `string-equal`（大小写不敏感）" → 76/76。
`d1-check-macro-1` 归一化成小写 → 6 条驼峰判据全挂（70/76）。

**差的不是能力，是歧义下的选择。** 这条歧义是我造成的（D5）。

### A.3 这一节的边界

- 每格 n=1（B 组 macro 有 2 格，仍不足以给区间）。
- 只有一个任务、一个模型族。
- **不能据此说"Lisp 更好"**。它只说明：在这个任务上，`compile-file` + `find-symbol` + 实跑 三件事，把失败从"全部"降到"局部"。
- `compile-file` 通过 ≠ 能跑：`(sb-ext:*posix-argv*)` 这种"把变量当函数调"的错误，编译期只警告，**运行期才炸**。所以"允许自检"必须包含实跑，不能只有编译。
- **自检不能替代外部判据**。本实验里自检强度最高的一格成绩最差；`d1-check-macro-2` 之所以过，是它在那条歧义上恰好猜对了方向，不是因为它查得更狠。
