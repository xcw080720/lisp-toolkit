# T2 宏的第二/三层实验（T2-b 优先）

> 独立于 `crossover.spec.md`。A 正在跑，**不要中途改它**；T2 等 A 交回后再接上，环境与判据完全复用。

## 为什么要单独做这个

昨晚量的都是「宏的第一层：声明去重」。**表驱动也能做到，判据打平。**
真正没测的是宏**在展开期**能做的事——尤其这一件：

> **它能不能挡住一个"测试挡不住"的错误？**

这不是修辞问题，有现成的对照组：昨晚两次假绿都发生在"判据没覆盖到新 op"上。宏在展开期看见的，比测试多。

## T2-b（优先，几十行）

### 需求

给 `defop` 加**展开期校验**，至少拦住四类：

| # | 非法形态 | 期望：在展开期报错 |
|---|---|---|
| 1 | 同名 op 注册两次 | 报错，指出重复的名字 |
| 2 | `:need` 里的字段不在 op 允许集合内 | 报错，指出字段名 |
| 3 | 缺 `:text` 或执行体为空 | 报错，指出缺哪一项 |
| 4 | op 名不是字符串 / 空串 | 报错 |

要求：报错信息必须**指出名字与原因**，不能只说 "invalid defop"。

### 判据（必须先证明能红）

```
C1  四条非法声明，各自 load 失败，且 stderr 含对应的 op 名与原因
C2  合法声明仍能 load，且 19 条不变量全绿（无回归）
C3  【核心】"测试挡不住、宏能挡住"的实证：
     注册两条同名 op、第二个覆盖第一个（或反之），
     恰好两条 body 对现有 19 条判据输出相同
     → check-scale 全绿，但宏在展开期报错
```

C3 是这轮唯一有价值的判据。**没有 C3，这轮不算数。**

### 要记的数

- 宏体新增行数（校验逻辑本身多少行）；
- 四条非法声明的报错首行（原文贴出）；
- C3 的对照结果：`check-scale` 跑通后的 output 哈希 vs 宏报错文本。

## T2-a（第二层：宏生成宏）

用 `defop-family` 一次生出一族同形状的宏，然后：

- 加第 6 个 op（同一形状）→ 记增量；
- 加**第 2 种形状**的一个 op → 记增量。

判：两类增量的比。若"新形状"的增量 ≈ "新 op" 的增量，二阶 DSL 不成立；若明显更低，成立。

## T2-c（第四层：产物扇出）

一条声明长出 6 样：执行体 / 文案 / 校验 / schema / 客户端 JS / 测试。

判（预注册）：产物数 1→6 时总行数增长 **< 2 倍** → 乘数成立；线性增长 → 扇出不成立。
