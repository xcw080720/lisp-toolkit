# relay：子 agent 转接子 agent —— 代码作为交接介质

## 为什么要测这个

深水里没有单打独斗。别人接你的活，**能不能跑起来**，决定了你的东西是资产还是遗产。

这一轮把"交接"拆成两个角色，只让第二个角色做事：

```
A 段：读实现，写一份交接文档（只能写文档，不许改代码）
B 段：fresh 上下文，只允许看「代码 + A 的文档」，加 3 个新需求
```

**测的是 B 的成本**：要读多少、误解几次、返工几轮。
A 的文档质量不计分（用统一模板，避免"谁更会写文档"这个变量）。

## 两臂

| 臂 | 交给 B 的实现 | 规模 |
|---|---|---|
| **CL** | `runs/iter-cl/impl.lisp` | 482 行 / 11578 字符 / 20/20 |
| **JS** | `runs/iter-js/impl.js` | 318 行 / 6128 字符 / 20/20 |

## A 段：交接文档模板（必须逐节填，不许增删章节）

```markdown
# HANDOFF

## 1. 这个程序在做什么（≤5 行）
## 2. 三个最重要的不变量（每条一行，说明破坏它会怎样）
## 3. 加一个新 op / 一个新行为，要改哪几处（按顺序列文件:行号）
## 4. 三处「看起来能改其实不能改」的地方（附原因）
## 5. 一个新人最可能在哪里理解错（你的猜测）
```

**A 不许写：**"实现很简单"、"照着加就行"、任何安慰性表述。
**A 不许改代码。**

## B 段：三个新需求（按顺序，一次一个）

### D4 `undo` —— 撤销上一条 op

新 op `undo`：撤销**紧邻的上一条** op，把状态恢复到那条 op 执行前。
- 若没有可撤销的 op，`undo` 不执行，日志 `撤销失败：无可撤销`；
- 若上一条是 `undo` 本身，则不执行，日志 `撤销失败：不能连续撤销`。

新增不变量：`add A` → `undo` → `courses` 为空，且 `n` 计数正确。

### D5 日志附加耗时序号

每条成功执行的 op，日志末尾加 ` [+k]`，k 是这次执行的 op 序号（从 1 起）。
`[skip]` 行不加。

新增不变量：一批 3 个 op（中间缺字段），`log[0]` 以 ` [+1]` 结尾，`log[2]` 以 ` [+3]` 结尾。

### D6 `stats` 增加"每门课被命中次数"

`stats` 的输出里追加 `hits`：每门课被 match 命中过几次。

新增不变量：`edit match=A` 两次 → `stats` 里 A 的 hits = 2。

## 记什么（B 段全部）

```
读了多少：读了哪几个文件、各多少字符、总共多少
D4 | 轮数 | 改动处 | 新增字符 | 有没有靠猜
D5 | ...
D6 | ...
误解清单：每一条写「我以为…，实际…」
文档里哪一句真的救了你 / 哪一句是废话
```

## 判据

- `node check-scale.cjs --impl impl.*` 必须 **20/20**
- B 自己的 `verify.cjs`：3 条新不变量，每条能红

## 预注册

```
H1  B 在 CL 臂上的「误解处数」更少     → 宏的单源结构更好交接
H2  B 在 JS 臂上「需要读的字符」更少   → 表驱动更自解释
H3  D4（undo）会让两臂都不得不新增"跨 op 状态" →
    这是继 iter 之后第二次撞到「跨 op 机制没有单一知识源」
否证：两臂 B 的轮数与误解数差异 <20% → 结构对交接质量无影响
```

## 铁律

- B **不许读** `runs/` 下任何其它目录、不许读 `tasks/` 以外任何 .md 报告、**不许读另一臂**；
- B 只许读：自己的实现文件 + 自己那份 HANDOFF.md + 本规格；
- A 与 B 必须是**不同的 fresh agent**；
- 中途不许问人。
