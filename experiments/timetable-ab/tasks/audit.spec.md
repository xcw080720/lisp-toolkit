# 横切关注点实验（audit）：一次给所有 op 加同一个能力

## 需求（三边一字不差）

给**每一个 op** 加审计记录：

- 每次 op 执行完毕（无论成功、跳过还是拒绝），向输出的 `audit` 数组追加一条：
  `{"op":"<op 名>","n":<本次改动的条数>}`
- `audit` 与实际执行的 op **一一对应、顺序一致**；
- 未知 op 触发整批拒绝时，`audit` 只含被拒绝的那一条：`{"op":"<那个未知 op>","n":0}`；
- 空 `ops` → `audit: []`。

## 判据（`check-audit.cjs`，必须全绿）

对**每一个已实现的 op** 单独跑一次：
1. `audit.length === 1`；
2. `audit[0].op === 该 op 名`；
3. `audit[0].n` 是数字。

再加两条整体断言：
4. 三个 op 连跑 → `audit.length === 3`，顺序与输入一致；
5. 空 ops → `audit.length === 0`。

## 要记的数（这是本轮的主指标）

| 指标 | 怎么数 |
|---|---|
| **改动处数** | 为实现这条能力，一共动了几个独立位置（必须逐处列出） |
| **改动行数** | 净增行 |
| **有没有漏** | 逐个 op 跑判据，有 op 没记上审计 = 漏（这是静默 bug） |

## 三边对照

| 臂 | 基线 | 预期 |
|---|---|---|
| Lisp 宏（`scale-lisp`，15 op，`defop`） | 467 行 | 改 **1 处**（宏体），0 处 per-op |
| JS 表驱动（`scale-js`，15 op，`REG`） | 308 行 | 改 **1–2 处**（`runOp` + 出参） |
| Lisp 无宏（`run3`，5 op，手写 `cond`） | 548 行 | 改 **5 处**（每个 op 一个分支） |

**判读**：若宏臂确实是 1 处而手写臂是每 op 一处，则"复利"成立——成本与 op 数无关。
这是本次唯一能判定"多次函数"的实验。
