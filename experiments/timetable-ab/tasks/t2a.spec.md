# t2a：宏生成宏（二阶 DSL）——它比普通宏多买到什么？

## 要回答的问题

普通宏已经做到"加一个 op = 一行声明"。那**加一种新的 op 形状**呢？

```
形状 A：match + 改字段        （现有 15 个 op 都是这一种）
形状 B：整个课表级操作        （排序 / 批量平移 / 按天过滤）
形状 C：只读统计              （按老师计数 / 按时段统计）
```

## 三臂（自变量：抽象的层级）

| 臂 | 机制 | 加"形状 B 的第一个 op"要做什么 |
|---|---|---|
| **S** 单宏 | 一个 `defop` 宏 | 改宏体（加一个形状分支） |
| **F** 宏生成宏 | `defop-family` 生出一族宏；每个形状一个宏 | `(defop-family :shape-b ...)` 一行 |
| **T** 表驱动（对照） | 一张 `OPS` 表 + 通用 `run` | 改 `run`（加一个形状分支） |

**核心预测**：

```
加第 2、3 种形状时：
  S：每次都要动那个唯一的宏（越改越复杂）
  F：每次只加一条"家族声明"，宏体不动
  T：每次都要动 run（和 S 同构）
→ 若 F 的单次成本 < S/T 且不随形状数增长，二阶 DSL 成立
```

## 任务

在现有实现上加 **3 种形状，每种 3 个 op**（共 9 个 op）：

| 形状 | op | 语义 |
|---|---|---|
| B 课表级 | `sortBy`（按 day,periodFrom 排序）/ `shiftAll`（全体节次 +1）/ `filterDay`（只留某天） | 对整表操作 |
| C 只读统计 | `countByTeacher` / `countByDay` / `busiestDay` | 不改数据，输出数字 |
| D 交叉引用 | `conflictOf`（某门课的时间冲突课）/ `sameTeacher`（同老师的所有课）/ `sameName` | 需要全表扫描 + 返回集合 |

形状 D 是故意加的：它既不改字段、也不是纯统计，**逼着抽象再长一层**。

## 判据

`check-t2a.cjs`：
- 每个新 op 一条不变量（9 条），每条都先证明能红；
- 原有 19 条（现 20 条）判据不能坏。

## 记账（本实验的全部重点）

```
加形状 B：改动处数 / 新增行数
加形状 C：同上
加形状 D：同上
每形状内第 2、3 个 op：改动处数 / 新增行数
```

**判读**：
- 若 F 臂的"每形状成本"**恒定**而 S/T 递增 → 二阶 DSL 成立（这是"复利"最纯的形状）
- 若三者都恒定 → 二阶 DSL 没买到东西，普通宏/表已到顶
- 若 F 更贵且不省 → 二阶 DSL 是负收益

## 预注册

```
H1  F 臂"每新增一种形状"的成本 ≤ S 臂的 1/2
H2  同形状内第 2、3 个 op，三臂都 ≤ 3 行/op
H3  形状 D（需返回集合）会逼所有臂都改一次公共设施——若三臂都改了，
    说明"返回类型"这一维是所有抽象的共同天花板
否证：H1 不成立 → 宏生成宏没有额外收益
```
