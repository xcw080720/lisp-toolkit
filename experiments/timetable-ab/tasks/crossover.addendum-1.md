# crossover 规格补充第 1 号（addendum-1）：上下文隔离

## 背景：规格漏了一条

`crossover.spec.md` 只写了"两臂串行、不并行"，**没写"两臂必须由不同 agent 在隔离上下文里跑"**。
一个 agent 连写两臂 → 第二臂会继承第一臂的设计（DSL 形状、字段命名、错误处理套路），
于是：

- `c_cl` / `c_js` 不再是语言属性，混进了"学习"；
- H1/H2（交叉点）被**顺序偏置**污染：后跑的那臂总是更快更短；
- H3（熟练度效应）**失去意义**——它测的正好是被污染的那部分。

## 现在该怎么处置（三种情况，对号入座）

### 情况 1：第一臂还没写完

- 第一臂照原样跑完，**结论标 `run-0（pilot，有跨臂风险）`**；
- 第二臂**新开一个 fresh 子 agent**：只给它 `crossover.spec.md` + 判据 + 环境变量，
  **不给**第一臂的代码、行数、结果、设计；
- run-0 的结论只作方向参考，不进最终表。

### 情况 2：两臂都由同一个 agent 写完了

- 整轮记作 **pilot**，`H1/H2/H3 不判**；
- 正式轮必须重开：**每个臂一个 fresh 子 agent**，且**顺序反转**（先 JS 后 CL），
  用来检验顺序偏置是否真实存在。

### 情况 3：还没开始

- 直接按下面"正式轮的正确姿势"跑。

## 正式轮的正确姿势（写死）

```
臂 1：fresh 子 agent A  ← 只给 spec + 判据 + 环境
臂 2：fresh 子 agent B  ← 同样，且 B 看不到 A 的任何产物
顺序：轮 1 先 CL 后 JS；轮 2（若做）先 JS 后 CL  → 抵消顺序效应
```

子 agent 的任务书里必须有一句：

> **不许读 `runs/crossover-*` 下任何其它目录；你的实现必须从零写。**

## 记录要求

报告里加一行：

```
上下文隔离：<fresh-agent-per-arm | 同 agent（作废）>
顺序：<CL→JS | JS→CL>
```

## 这条要写进长期协议

> **凡是比较两个臂"写得多快/多短"的实验，两臂必须由隔离上下文的 agent 各写一次。**
> 否则测的是"第二个臂借了第一个臂的脑子"。
