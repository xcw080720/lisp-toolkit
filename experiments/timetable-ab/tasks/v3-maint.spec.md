# v3 维护规格：全局规则 `--dry`

> 用于"改动半径"实验。目标不是加新 op，而是**改一条影响全部 op 的规则**，看两臂各要动几处。

## 规则

任意命令前可加前缀 `--dry`：

```
--dry <原命令及其参数...>
```

语义：
- 照常解析、照常校验、照常输出 `ok <verb> <n>` 或 `err <CODE>`
- **但不改变课表状态**（预演）
- `n` 语义不变：`add` 报 1（即便没真的加）、`del` 报 1、`clear` 报该天课程数、`trim` 报将被截断的门数……即「**将会影响的数量**」
- `--dry` 单独出现（后面没有命令）→ `err BADARG`
- 出错时照旧 `err <CODE>`（预演不掩盖错误）

## 判据

| id | 内容 |
|---|---|
| 52 | `--dry add a t r 1 1 2` → `ok add 1`，`#state` 为空 |
| 53 | `add a ...` 后 `--dry del a` → `ok del 1`，`a` 仍在 |
| 54 | 两门课后 `--dry clear 1` → `ok clear 2`，两门都还在 |
| 55 | `add a` → `--dry del a` → `count` → `ok count 1`（状态没被预演影响） |
| 56 | `--dry del ghost` → `err NOTFOUND` |

## 度量（这次的关键指标，不是字符）

| 指标 | 定义 |
|---|---|
| **必须修改的既有行数** | diff 中 `−` 行数 + 因语义改变而必须重写的行数（不是纯追加行数） |
| **改动位置数** | 必须触及的既有代码片段个数（不是 diff hunk 数） |
| Δchars | 总字符增量 |

预期（待验）：
- macro：宏里 1 处判断 → 全部 op 生效 → **改动位置 ≈ 1**
- inline：30 个分支各加判断 → **改动位置 ≈ 30**

## 注意

如果 macro 臂发现无法一处改完（例如每个 op 的执行体都要改），**照实记录**——那说明"改动只动一处"这个说法有前提条件，而那些前提条件正是要写进报告的。
