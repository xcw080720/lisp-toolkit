# HANDOFF

## 1. 这个程序在做什么（≤5 行）

读一个 JSON 任务包（`courses` 初始列表 + `ops` 指令数组），按顺序执行 15 个课表 op，写出 `opsText` / `courses` / `log` / `n`。
入口 `(main)` 在 impl.lisp:462，末行 481 直接调用；输入路径取 `sb-ext:*posix-argv*` 的**最后一个**元素(463)——加任何命令行开关都会顶掉路径。
op 由 `defop`(252) / `defop-each`(256) 注册进 `*op-table*`，`run-op`(268) 是唯一分发点，`run-all`(426) 是唯一循环兼日志工厂。
状态只有一份：special 变量 `*courses*`(164) 里的 `course` 结构体列表，op 一律原地 `setf` 字段。
输出侧 `emit`(445) 只做序列化，非 ASCII 全部转 `\uXXXX`(121)，为的是绕开 Windows 管道编码。

## 2. 三个最重要的不变量（每条一行，说明破坏它会怎样）

- **identity：`*courses*` 里的结构体对象就是唯一真身，op 只原地改字段、从不"复制后替换"**——一旦某处改成函数式替换，`del`/`clear` 的 `set-difference :test #'eq`(301,378)、`swap` 的同门判定 `(eq (car a) (car b))`(344)、`sort` 的换位计数 `(eq x y)`(405) 三处同时静默错掉，而 `add`/`edit` 的文案仍然是对的，很难看出坏在哪儿。
- **op 名册单源：`*op-table*` + `*op-order*`(233-234) 是"有哪些 op"的唯一答案，写入只在 `register-op`(238-239)，读出只在 242/270/442/475**——一旦另开一条 `case`/`if` 分派，未知 op 判定(439-443)与报错里的可用名册(474-475)就和"实际能不能执行"分叉，表现是某个 op 能跑但不在名册里，判据里只有未知 op 那一条会红。
- **日志与 `n` 只有一个出口：`run-all`(426-437)，序号 `i` 只对非 skip 行递增(435)，`n` 只在 430 累加**——一旦在 op body 或 `defop-each`(263-266) 里自己拼日志，就有了两个互不知道的来源，`[skip]` 与 `k) ` 的对应关系断掉，`n` 与日志条数不再可比，给日志加后缀时会双重编号。

## 3. 加一个新 op / 一个新行为，要改哪几处（按顺序列 文件:行号）

**A. 加一个新 op（不动数据模型）**

1. impl.lisp:256-266 —— 先选形态：命中式用 `defop-each`（自动产生"命中 N 门"文案与计数），整批式用 `defop`(252-254)。`fields` 列表即参数校验契约，`missing-fields`(249) 直接吃它。
2. 新表单放在 impl.lisp:280 之后、462 之前即可，**但插入位置有语义**：`push`(239) + `reverse`(242) 让名册顺序等于源码顺序，而名册会被拼进 474 的未知 op 文案——插在中间等于改一条输出。
3. 不要动 impl.lisp:439-443（`unknown-op-name`）与 469-479（`main` 的 cond）：注册在宏展开/加载时就发生，新 op 自动被认。
4. 若新 op 需要"不执行"语义：直接 `(values 0 文案 t)`。278 是 `(funcall ...)` 裸调用，多值原样透传，第三值 `t` 会走 432-433 的 `[skip]` 分支——这条通道没有任何文档写明，但比改 `run-op` 便宜。
5. 若新 op 需要"跨 op 记住点什么"（undo 就是）：没有现成位置。要新增 `defvar`（挨着 164 或 233-234），并挂进 `run-all` 的两处：`429` 取返回值、`430` 改 `n`；`run-op`(268-278) 只回 `cnt/msg/skip` 三个值，装不下"上一条 op 的前像"，`log` 里也只有成品字符串。
6. 自测只跑 `check-scale.cjs`，不要新增注册代码，也不要为新 op 另写第二份字段表。

**B. 加一个不改 op 表的新行为（日志 / 统计型）**

1. 日志后缀这类：只改 impl.lisp:436，`i` 就是"第几条成功 op"，与 D5 要的 k 同义；432-433 的 skip 分支不要动。
2. 但 impl.lisp:474 是**手写**的编号日志（`"1) 拒绝：…"`），它不经过 `run-all`；改编号规则时这是第二个会漂的点。
3. 命中统计这类：唯一能看见"全部命中"的位置是 impl.lisp:216-218（`matched`），它在 7 处被调用（260/297/306/330/342/343/360），其中 342-343 一个 op 调两遍（`match` 与 `with`），在 `matched` 里无脑 `incf` 会把 `swap` 记成两倍；`clear`(377) 按 day 选、`untag`(392-393) 按 tag 相等选，都绕开 `matched`。
4. 配套字段要落地在四处硬拷贝：impl.lisp:163（`defstruct`）→ 189-198（读入）→ 200-208（写出）→ 210-214（`clone-course`）；只改其中一处会出现"算出来了但写不出去"或"`duplicate` 之后字段丢失"。

## 4. 三处「看起来能改其实不能改」的地方（附原因）

- **impl.lisp:400 的 `(copy-list *courses*)`——不是多余的保护，是 `moved` 的唯一来源。** `stable-sort` 是破坏性的：不复制，`old`(399) 与 `new` 就是同一批 cons，`old` 的头会被原地接走，405 的逐位 `eq` 比较变成拿两个长度都可能不同的切片对齐，`moved` 得到无意义的数，`sort` 文案（"0 门课换位"/"N 门课换位"）随之失真，而排序结果看起来完全正确。判据里比对 `sort` 计数或文案的用例会红。
- **impl.lisp:344 的 `(not (eq (car a) (car b)))`——不是防御性冗余，是 `n` 的闸门。** 两个模式命中同一门课时，删掉守卫会让 `x` 与 `y` 是同一对象：字段读写互相覆盖成原值（课表不变），但返回值仍是 `2`，`n` 被凭空加 2，文案还自信地写"互换「A」与「A」"。只要有一个 `swap match=A with=A` 的用例就会红。
- **impl.lisp:284 只在 `add` 里挂了 `unique-name`，`edit`(313) 与 `rename`(357) 直接 `setf name`——看起来是漏了一句，补上就出事。** 同名课是这套数据结构允许的状态：补上序号会让 `edit` 的"命中 N 门"与 `duplicate` 的结果整体偏移；反过来，任何"用 name 当键"的做法（比如统计每门课被命中几次）都会直接踩到"两门课同名"。要么按结构体 `eq` 建表，要么别做这个功能。

## 5. 一个新人最可能在哪里理解错（你的猜测）

文件头 2-3 行说"参数校验、日志序号、文案、执行分发、可用 op 名册全部由宏生长出来"——**这句话是错的，而且错的方向恰好是新人要动手的方向**。宏（252/256）真正长出来的只有：字段清单校验、注册（名册与分发）、以及 `defop-each` 那种"命中数 + 固定句式"的骨架；**日志序号根本不在宏里，它是 `run-all` 的局部变量 `i`(427/435/436)**，文案也不是生成的，是每条 op 手写的 `fmt`。于是新人要加"日志末尾序号"时会去 `defop-each` 的 `fmt`(265-266) 里拼字符串——那里既拿不到 `i`，又会连 `[skip]` 行一起污染，序号语义也与 `k) ` 无关。

紧随其后的第二处误解是 `cnt`：它不是统一的"改动数"，而是每个 op 自己解释的数字——`add` 恒 1(291)、`del` 返回删除门数(302)、`edit`/`trim`/`rename` 返回**命中**门数(325,264)、`sort` 返回换位门数(405)、`stats` 恒 0(422)。`n`(430) 是这些数相加，所以 `n` 不等于"改了多少"。把 `cnt` 当作 diff 大小去做 undo 的 `n` 回滚，会在 `trim`（命中但可能零改动）和 `sort`（可能零换位）上算错。
