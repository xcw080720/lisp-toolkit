fanout-java 臂（注解处理器）运行记录
=====================================

管道：decls.json（唯一声明源） -> Emit 生成 @Op 注解源 -> javac 两趟（第 1 趟编处理器、
第 2 趟带 -processor 只编注解源） -> GenProc 用 Filer 在编译期落 5 样产物。

产物出口：**Filer 资源接口**（createResource + CLASS_OUTPUT），不是 Files.write。
因此 Emit 把 javac 的 -d 指到工作目录根，产物直接落在判据要看的位置。

复现
----
    javac -encoding UTF-8 -d . Emit.java        # 只编 Emit（处理器在运行时由 Emit 编）
    java -cp . Emit                             # 生成 5 样（+1 样实验产物）
    node ..\..\check-fanout.cjs --dir .         # 判据

判据能红的证据
------------
build/red/ 里放了「生成器写死」的对照（emit.cjs 直接 exit 0，产物保持上一次内容）：
    同步A FAIL（emit=true changed=false）
    同步B FAIL（emit=true schema=false client=false）
说明 18 项判据不是恒真，它测的确实是「声明改了产物跟不跟」。

已知的两处真实代价（都在代码里留了注释）
----
1. swap 的形参名 with 是 JS 保留字：client.js 里改叫 with_，但对象键仍是 with，
   保证 schema/校验用原声明名。任何跨语言生成器都会撞上这类命名冲突。
2. -d 同时是 class 输出目录，所以工作目录根会多出 gen/OpsDecl.class；产物目录和
   class 目录在 APT 里是同一个开关，这是 Filer 按位置出口带来的副作用。
