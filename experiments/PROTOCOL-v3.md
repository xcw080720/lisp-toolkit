# PROTOCOL v3 — 12 次最小可统计设计

> 2026-10-31 起草。取代 v1/v2 的"多跑几个 run"思路。
> 已发布数据（81 run，v1.1.2）降级为**探索性附录**：它记录的是设计演化过程，不是结论来源。

---

## 0. 一句话

**2 语言 × 2 方案 × 3 次独立重复 = 12 次生成**，任务固定、规模固定、禁用 JSON I/O。
目的是第一次拿到**有方差的**数据，让 `first_pass` / `rework_rounds` / `silent_failures` 三列从全空变成有数。

## 1. 为什么必须重跑（三条硬缺陷）

| 缺陷 | 现状 | 重跑怎么修 |
|---|---|---|
| 没有重复 | 15 op 层 CL 3 份、JS 4 个独立值（其中一个值被登记 11 次） | 每格 3 次独立生成 |
| 没有配对 | 只有 15/16 op 有 JS 对照 | 固定 15 op，四格全配 |
| 核心指标全空 | `first_pass`/`rework_rounds`/`silent_failures` 81 行全空 | 每次生成都记 |

## 2. 设计矩阵

| 臂 | 语言 | 方案 | 重复 | run 目录 |
|---|---|---|---|---|
| A1–A3 | Common Lisp | 宏 DSL（单源表单） | 3 | `runs/v3-cl-macro-r{1,2,3}` |
| B1–B3 | Common Lisp | 内联（每个 op 手写分支） | 3 | `runs/v3-cl-inline-r{1,2,3}` |
| C1–C3 | JavaScript | 表驱动（注册表） | 3 | `runs/v3-js-table-r{1,2,3}` |
| D1–D3 | JavaScript | 内联 | 3 | `runs/v3-js-inline-r{1,2,3}` |

**方案维度是必须的**：上一轮已证明比值跨方案稳定（1.89 / 1.93 / 2.16），但那只有 n=1。这次每格 3 份，才能给出方案×语言的交互项。

## 3. 任务定义（固定，不得改）

- 规格文件：**`tasks/v3.spec.md`**（v3 专用，与旧 `scale.spec.md` 不同）
- op 数：**15**
- **禁止任何 JSON / 序列化 / 文件 I/O**：输入用命令行参数，输出用 stdout 的纯文本行
  - 理由：JSON 生态差异已量化（CL 2547 字符 vs JS 233），会吃掉 40% 的差异。v3 把它从实验里拿掉，只测"语言 + 方案"。
- 判据：`node check-v3.cjs --impl <file> --upto 36`，目标 **全绿**
  - 36 条判据从旧集迁移，凡依赖 JSON 的条目替换为等价的纯文本断言；替换清单见 §7

## 4. 什么叫"一次独立生成"（判定规则，先定死）

一次生成必须同时满足：

1. **新会话**：子代理上下文不继承前一次的任何代码（不给上一份 impl，不给上一份的报错）
2. **同一份提示**：使用 §5 的模板，逐字不改（除臂名/语言/方案三项）
3. **不人工干预**：生成过程中不提示、不补代码、不指路
4. **留全档**：`prompt.txt`（实际发出的提示原文）+ `impl.*` + `log.txt`

不满足任一条 → 该次作废，标记 `invalid`，不计入 n。

## 5. 提示模板（逐字使用）

```
你要完成一个任务，只输出代码，不要解释。

【语言】{{LANG}}
【实现风格】{{STYLE}}
【规格】见下（附全文）

【约束】
- 只能用一个文件。
- 不许读写文件、不许 JSON、不许任何序列化。
- 输入从 argv 读，输出用标准输出，每行一条结果。
- 不许引入第三方库。
- 写完不要自测，不要解释，直接给代码。

【规格】
{{SPEC_FULL}}
```

`STYLE` 三个取值，措辞固定：

- `macro`：用宏把每个 op 的定义收敛到一处，校验/文案/分发由宏生成
- `inline`：每个 op 手写独立分支，不共用任何生成机制
- `table`：用一张注册表描述所有 op，执行器读表分发

## 6. 每次生成要记的六个数

| 字段 | 定义 | 怎么取 |
|---|---|---|
| `first_pass` | 首次提交是否一次全绿 | `check-v3` 第一次运行的退出码 |
| `rework_rounds` | 从首次提交到全绿用了几轮修改 | 每轮 = 一次新的 agent 回合；轮数 = 全绿前的回合数 |
| `silent_failures` | 编译通过、退出码 0、但结果错的次数 | 判据失败但程序未崩溃的次数（逐轮累计） |
| `chars_core` | 非空白非注释字符（v3 无 I/O，故全部算 core） | `node metric.cjs <file>` |
| `chars_io` | v3 应为 **0** | 若 >0，说明 agent 违反约束，记 `note` |
| `t_green` | 到全绿的墙钟分钟 | 手动记，开始/结束时间 |

## 8. 预注册假设

```
H1  同 op 数、同方案下，CL 的 chars_core > JS 的 chars_core
    判据：四格的中位数差 > 0 且 bootstrap 95% CI 不跨零

H2  宏/表驱动方案的 chars_core < 内联方案（两语言皆然）
    判据：同语言内 median(宏 or 表) < median(内联)

H3  first_pass 与语言无关，与方案有关
    判据：同方案跨语言的 first_pass 差 < 同语言跨方案的差

H4  弱执行者才会产生 silent_failures
    判据：强模型下 silent_failures 中位数 = 0（则本条在强模型上不可判，转 C1）
```

任一假设被否证 → 记入 `CLAIMS.md`，不解释、不挽救。
